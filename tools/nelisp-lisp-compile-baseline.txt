# diagnostic count.  Every other lisp/*.el must produce zero diagnostics.

# Each number is a CEILING, not an equality.  It has to be: these counts are
# Emacs-version sensitive.  They were measured on 31.1; CI runs 29.4 and 30.1,
# where `nelisp-cl-macros.el' reports 1 rather than 3 and
# `nelisp-stdlib-eval-special.el' 3 rather than 4, because 31.1 added warnings
# older compilers do not emit ("docstring wider than 80 characters", "not known
# to be defined").  Pinning equality failed on the first CI run for exactly
# that reason.  A count that RISES fails; a count that falls is reported and
# passes.  A baselined file that disappears from the tree still fails.
#
# Measured 2026-09-12 on Emacs 31.1 by tools/nelisp-lisp-byte-compile-gate.sh,
# which compiles ONE FILE PER PROCESS.  That matters: the first version of
# this baseline was taken from a single `batch-byte-compile lisp/*.el' run and
# recorded 2 files / 107 diagnostics.  Compiling the same tree one file per
# process reports 39 files / 312 diagnostics -- the batch form hid 37 files
# entirely, including a deliberately injected defect, because an earlier file
# in the batch had already `require'd the later one.  Do not "simplify" this
# gate back into one batch.
#
# Re-pinned 2026-11-13 (user approved) after the byte-compile cleanup
# (B0-B9): 39 files / 314 diagnostics -> 24 files / 87.  Both artifact.el
# and aot-compiler.el entries above were resolved: artifact.el now compiles
# clean (the condition macros are required at compile time), and
# aot-compiler.el keeps 2 (a duplicated defun and one obsolete call).
#

# cannot change without moving that pin:
#   nelisp-timefns.el 6, nelisp-cl-macros.el 5 (was 3): prelude files whose
