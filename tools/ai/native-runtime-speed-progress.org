#+TITLE: Native runtime speed for string-heavy code and native cache loads

# Objective: make native-compiled, string-heavy code (the Windows SKK IME
# merge functions, the GUI functions) fast in practice.  Native codegen is
# not the bottleneck.  Native code reaches substring, string=, equal
# through bytecode-opcode builtin tokens, but split-string,
# string-prefix-p (compare-strings) and multibyte string-search run as
# interpreted prelude/GNU Lisp, and the interpreter itself is slow: a
# two-binding let makes ~107 heap allocations (immediates read out of
# conses, records and vectors are boxed into fresh 32-byte slots; the
# special-variable test walks the frame's local names and a registry),
# so 38% of the time is allocation and 38% is mid-form GC (0.23 s each).
# Loading a native cache spends most of its time base64-decoding the
# artifact text in interpreted Lisp.
#
# Checks run a built reader named by NELISP_RT_BIN from the repo root.
# Baseline (integ 90eb52275 dynamic reader, 2026-10-12): let2/let1 3.42,
# 100000/1000-iteration let loop 1.65, substring/native 9.50,
# string=/native 12.91, split-string of 32K chars 0.63 s,
# string-prefix-p 1133 us/call (compare-strings 1081 us).

* S1 split-string scans natively

* S5 Garbage in cold-image holes is collected

# A cold image carries the dumping run's freed blocks (425 MB bump, ~52 MB
# live for target/nelisp-static.cold).  They are relinked and reused, but
# the sweep kept every non-free block below the boot watermark, so garbage
# placed in a hole was never reclaimed: live grew ~288 bytes per loop
# iteration until the holes were used up, and each collection grew with it.
# Baseline (integ 12e80e238 dynamic reader, 2026-10-14): loop +71 MB,
# cons +97 MB, GC pause 0.29 s -> 0.99 s after 2M iterations of churn.
# Truthful live bytes make collections ~5x more frequent in a GUI image,
# which exposed the symbol-name sidecar keeping every tombstone of dead
# gensyms: its empty slots ran out and every new name probed the whole
# table (GUI daily S5.1 slowed until it timed out).  Baseline (integ
# 9481f6010 dynamic reader, 2026-10-15): S5.4 fails at round 3, 3000
# gensyms 0.172 s versus 0.031 s in the first round.

** S5.1 Three 100000-iteration counting loops leave under 1 MiB of live growth on a cold image
cmd: GC_CHECK=loop $NELISP_RT_BIN --cold-load-from $NELISP_RT_BIN.cold --load test/standalone-gc-image-hole-check.el

** S5.2 200000 discarded conses leave under 1 MiB of live growth on a cold image
cmd: GC_CHECK=cons $NELISP_RT_BIN --cold-load-from $NELISP_RT_BIN.cold --load test/standalone-gc-image-hole-check.el

** S5.3 One collection after 2M iterations of churn takes at most 1.5 x (+0.05 s) what it took before
cmd: GC_CHECK=pause $NELISP_RT_BIN --cold-load-from $NELISP_RT_BIN.cold --load test/standalone-gc-image-hole-check.el

** S5.4 Over 40 rounds of 3000 named gensyms and a collection, no round costs more than 4x the first
#+REQUIRES: NELISP_RT_BIN
#+TIMEOUT: 120
cmd: $NELISP_RT_BIN --cold-load-from $NELISP_RT_BIN.cold --load test/standalone-symname-tombstone-check.el
