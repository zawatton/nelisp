# GNU uses typed blocks (cons, float, symbol, string and sdata, vector
# blocks, large vectors), side mark bitmaps, persistent address-range
# metadata (the mem_node tree) for conservative scanning, and per-type
# free lists rebuilt by per-type sweeps. NeLisp uses a general block
# allocator, separate header and payload allocations, a temporary
# exact-start index rebuilt each GC, and heap-wide coalescing. Doc 216 (the
# word heap) removes header boxes but provides no typed pools; this
# objective adds them inside the word-heap design.

* S1 Implementation and semantics
** S1.1 Conses are allocated from GNU-style cons blocks
The blocks carry side mark bits and a free list. Sweeping is per type, and there is no exact-start index or heap-wide coalescing for conses. Semantics hold: the GC stress and conservative-scanning tests pass on dynamic and static.
#+NOTE: 2026-10-21: ported GNU alloc.c cons blocks. Fcons (alloc.c:2599) -> nl_cons_alloc: cons_free_list pop, cons_block_index bump, new 32 KiB block from 512 KiB groups (lisp_align_malloc alloc.c:1060, BLOCK_ALIGN alloc.c:937, ABLOCKS_SIZE alloc.c:979). struct cons_block (alloc.c:2539) layout: cells, gcmarkbits, next; CONS_BLOCK_SIZE (alloc.c:2526) is 1356 for 24-byte cells (adapted: the refcount word stays until word-heap S2.2). XMARK_CONS (alloc.c:2550) side bits; mark_object's cons case (alloc.c:6733) takes no exact-start probe. sweep_conses (alloc.c:6814) ported with the all-marked fast path, the dead car marker and block release. mem_find (alloc.c:4213) adapted as an open-addressing registry of aligned groups with GNU's min/max address rejection; live_cons_holding (alloc.c:4627) and mark_maybe_pointer (alloc.c:4854) ported for the conservative stack scan. Images: pdumper's object copy adapted, the stream dump appends each cell as a legacy headered payload, so the loader is unchanged. Parallel sections keep the legacy CAS path (GNU's free list has one writer). gcstat (alloc.c:6886): an explicit garbage-collect counts block conses from sweep_conses and skips image objects, as GNU never counts pdumper objects.
