#+TITLE: Symbols decision item A: a symbol object's name cell holds the String WORD (GNU u.s.name)

# Decision item A of the word-heap batch (tools/ai/integ-wh-progress.org S2.9), owner: the symbols lane
# agent.  Base: eval/core-20261017 at 63ec9640e (the batch's tip: symbols, gc-port, strings, hashtab,
# callpath and codegen merged).  Branch: eval/symbols-name-word-20261024.
#
# What changes.  GNU lisp.h struct Lisp_Symbol.u.s.name is a Lisp string object.  The batch chose design B
# (c8188b40a): the name cell of an interned symbol object keeps a legacy 32-byte name box over arena bytes
# (nl_symname_make via nl_alloc_str_write_legacy), because the symbols lane's grammar emitters redirect a
# symbol object to its name cell and require a legacy view there.  B costs a second copy of every name in
# arena bytes, a legacy box cannot say that ASCII bytes are multibyte (bit 62 of the capacity word carries
# it, fix 17), and every consumer needs the view-versus-WORD care that fixes 13, 16, 17 and 18 needed.
# Design A: the name cell holds the canonical String WORD for interned and uninterned symbols; the producers
# (nl_symname_make, nl_sym_make_uninterned, intern, the reader, the symbol-name side table) yield it; the
# emitters (emit-symbol-object-redirect and the name ops, x86-64 and arm64) and the physical-read functions
# (nelisp_env_*, nl_gc_*, the mirror) read it.  Strings layout (docs/design/227): header at WORD-4, data
# pointer at WORD+20, size at +0 and size_byte at +8 of the header (size_byte negative = unibyte, the byte
# length is then size with its top bit cleared).
#
# B's conditions from the batch stay green (integ-wh-progress S2.7 and S2.8): every name writer is
# enumerated, a symbol's names survive a dump and a second-generation dump at scale on both linkages, and
# (eq (symbol-name 'ab) (symbol-name 'ab)) is t through two generations.
#
# Decision carried into A, stated here so it is not read as an accident: `intern' keeps its private copy.
# GNU 31.1 aliases the caller's string (intern then aset changes the symbol's name and (eq (symbol-name sym)
# s) is t); NeLisp at 63ec9640e copies it (the name stays "zzq", eq is nil), because an interned name's key
# bytes live in the permanent intern region and a mutable name String would diverge from them.  A keeps that
# divergence: bf_intern_w makes the private String before the side table registers it, while the reader
# adopts its own token String (fresh per token, never visible to Lisp) as the name.  make-symbol shares its
# argument as GNU's Fmake_symbol does.  S1.2 pins this with REP lines (they are not compared with GNU).
#
# Which emitters are production-reachable.  nelisp-heap-accessors-lower rewrites str-len, str-bytes,
# str-byte-at, str-eq and sexp-name-eq into String-aware code before any emitter sees them, so at 63ec9640e
# only symbol-name-eq (not lowered) and symbol-eq reach the machine emitters of the runtime build.  The
# critical ones are emit-symbol-name-eq (x86-64 and arm64) and emit-symbol-object-redirect; emit-symbol-eq's
# view path is unaffected (a symbol object goes through nl_symbol_word_eq, which reads names with
# nl_word_data and nl_word_length).  The other emitters are still grammar operations that the compiler's own
# tests and any unlowered caller use, so S2.2 and S2.3 test them too, with the lowering off for the probe.
#
# Coordination.  Another agent changes the collector's string-area handling and make-string on
# eval/integ-wh-20261022-m12.  This lane does not touch those functions (S0.2 checks the changed-defun set
# against 63ec9640e); a marker change, if the symbol arm needs one, is said so in its commit message.
#
# Verification limits, stated before any code change.  arm64 binaries of the runtime cannot be built or run
# on this x86-64 machine.  The arm64 emitters are verified by compiling probe programs with the AOT
# compiler's aarch64 back end and executing them under qemu-aarch64 (user mode, ~/bin/qemu-aarch64); that
# proves the emitted instructions on the ISA, not a full arm64 runtime.  The arm64 name ops had no symbol
# object redirect at all at 63ec9640e (only the x86-64 ones did): found while reading, reported, and
# covered by S2.3.
#
# Binaries.  SNW_DYN and SNW_STATIC (default target/integ/nelisp-dyn and nelisp-static) are this branch's
# builds (tools/ai/integ-wh-build.sh, LINKAGE=static for the static one); SNW_BASE_DYN and SNW_BASE_STATIC
# (default target/base/nelisp-dyn and nelisp-static) are the batch's E binaries (built from 3ed3be627,
# whose build inputs equal 63ec9640e's: the two commits differ only in tools/ and the ledger), copied
# unchanged.  Evidence of the long runs is read from target/snw/logs/ (tools/ai/symbols-name-word-check.sh
# run UNIT writes it, each log names the sha256 of the binaries it ran), as the batch ledger reads
# target/final-verify/.
#
# Pre-registered measurement bounds (S5), fixed before the first measurement of the candidate: ratios are
# candidate over baseline, medians of paired alternating rounds on one CPU (SNW_CPU, default 13): reader
# first read of 30,000 new names at most 1.10, reader repeat at most 1.05; intern of new names at most
# 1.10, of existing names 1.05; symbol-name per call 1.05; startup 1.05; cold image size 1.01; gc3 worst
# median ratio against GNU at most 1.20 (the batch's bound) and at most the baseline's plus 0.05.
#
# Every REPL and test runs under ulimit -v 8388608; heavy units go through bin/heavy-run.sh.
