* Product decision and acceptance boundary

- Application Lisp executes in the genuine NeLisp runtime compiled to Wasm.
- A fixed JavaScript adapter may load Wasm and expose browser capabilities.
- Do not transpile application logic to JavaScript or implement Lisp builtins
  in a JavaScript dispatcher.
- This is a new browser target, not an ECMAScript-compatible engine or an npm
  compatibility promise. TypeScript-equivalent static checking is separate.
- Do not reduce W0 to a numeric demo or claim runtime readiness from provider
  compilation, opcode tests, or simulated-browser checks.

W0 exits only when an actual Wasm core evaluates a portable application image
using cons/car, string concatenation and a captured closure, producing the
equivalent of =(7 "NeLisp" 9)=. Removing its genuine Wasm builtin provider must
make the fixture fail. No JavaScript evaluation fallback is allowed.

The design is in =docs/design/213-web-application-platform.org= and its review
in =docs/design/213-web-application-review.org=. They remain DRAFT. The design
deliverable ledger reaching 100% is not runtime readiness.
