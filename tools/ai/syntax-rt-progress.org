** S1.3 string-match own cost <= GNU's own cost for a plain and a syntax-class pattern on a short string (wall-clock)
#+NOTE: 2026-10-21 P2 (ported): the matcher reads the current syntax table once per match and tests each character's raw descriptor directly, as GNU regex-emacs.c:5175-5200 tests SYNTAX (c) after one RE_SETUP_SYNTAX_TABLE_FOR_OBJECT (:3462), instead of calling char-syntax per character; a provider whose table is not a char-table still answers through its char-syntax. Paired ratios on CPU 10 (7 rounds): (string-match "\\sw+" "alpha") own cost 243 us against the base's 5,042 us in a loaded run (ratio to base 0.099); GNU 0.20 us.
#+NOTE: 2026-10-21 P3 (ported): the entry reads the current buffer's canonicalize table once, as GNU string_match_1 reads BVAR (current_buffer, case_canon_table) (search.c:405-410), through case-table--search-canon instead of four dispatch layers, and translates a character as GNU char_table_translate does (character.h:592): one aref on a native table. When the table is the pristine standard one, whose mapping equals the matcher's built-in fold for all 1,114,112 Unicode scalars (tools/ai/syntax-rt-canon-scan.el: 0 mismatches), the search uses the built-in fold and its plans; GNU likewise trusts a translate table's identity for its compiled-pattern cache (search.c:220). This undoes batch D's fold regression (regex6000's pattern 68 us in batch C, 1,103 us in batch D). Paired ratios, 7 rounds on CPU 10: plain own cost 89.6 us (base 433.1, ratio 0.206), \\sw+ 213.6 us (base 2,426, ratio 0.088); GNU 0.13 and 0.20 us.
