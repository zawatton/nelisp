* S1 Source
** S1.1 The compiler emits, for every call site in every generated function with a frame pointer, a map of the frame slots live after the call (type-conservative, liveness-exact as in DESIGN.md, with the documented full-frame fallbacks), into a self-relative table usable on SysV and PE; the per-target no-data-blob rule holds; emitted-table red/green on small functions with known liveness
#+NOTE: Liveness is per fixed-frame word (slot number = word index below rbp), flow-sensitive on the IR (seq, let-rt, let-rt-n, setq, if, cond, logic, while to a fixpoint), order independent as in DESIGN.md 2 (a node's set is live-after U slots read inside it). Sites are the E8 call placeholders of the final text (relocs and label fixups), attributed to the innermost emitted node range; a site in no range would be FULL (none occurred). Documented FULL functions: variadic, gc-root-slots, internal-entry, self-tco-raw, observer kinds (aot-*, va-*, frame-alloc, syscall, wasm), alias plans, frameless leaves, every non-SysV or non-x86_64 function (so Win64/PE gets the table format with FULL entries only; Win64 slot maps are a later stage). Private-let functions are mapped but flagged (fflags bit1) for the stage-2 audit. No hook in the assembler: lisp/nelisp-asm-x86_64.el is untouched. Red = seed compiler fails all 12 tests (red-seed.log), green = 12/12.

** S1.2 Shadow mode: under a debug switch, the collector walks the rbp chain, looks up each return address, and logs every word the conservative scan marks that the maps exclude (with frame, function, slot offset); default behaviour (switch off) is byte-identical in what it marks; a negative control shows the walker detects a deliberately wrong map entry
#+NOTE: Mode, counters and log buffer live in stackmap.o's own bss block (nl_stackmap_state); switches 90 (enable), 91, 92 K (read word K), 93 (clear), 94 V (INVERT every map bit: the negative control), 95 V (stderr log, 4000-line cap), 96 K. The walk runs after the real nl_gc_conserv_scan loop and only reads (nl_gc_conserv_resolve / nl_string_mapping_holding), so a collection marks exactly what it marked before; with the switch on, its own stack frames leave residue, so marks of LATER collections can differ (seen with the negative control), which is why only switch-off equality is claimed. The live-role check is a geometry check (live bit on a non-slot word = 0, frame region >= fixed words = 0 violations); the control flips every bit and trips it (400 on the probe).
