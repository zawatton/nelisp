* At-risk details

** lisp/nelisp-native-load.el:773 nelisp-native-load-box (string case)

Path: the caller passes a Sexp slot ADDR (typically alloc-bytes 32 8). The string branch copies bytes to a temporary buf, then ptr-call nl_alloc_str writes a runtime string object whose pointer lives only in the slot at ADDR. If ADDR is later reachable only from another raw buffer (for example an argument table) and a GC runs, the string payload is not reached. The slot buffer itself is pinned only while a Lisp integer holds ADDR.

Fixture sketch: A = (alloc-bytes 32 8); (nelisp-native-load-box A "hello"); B = (alloc-bytes 32 8); (ptr-write-u64 B 0 A); setq A nil; run a while loop with allocation plus (garbage-collect); then read through (ptr-read-u64 B 0) with nelisp-native-load-unbox. Expect corrupted or stale bytes if the slot or string was swept.

** lisp/nelisp-native-load.el:857 nelisp-native-load--make-scratch-vector

Path: nl_alloc_vector returns BOX, held in let var box only until the function returns; it is then stored with ptr-write-u64 into raw ADDR slot (offset 8). Each element cell (alloc-bytes 32 8) holds a boxed string and is dropped after nl_vector_set_slot copies it, so the element strings and the vector box are reachable only through raw memory. A GC after return frees the box while ADDR still points at it.

Fixture sketch: A = (alloc-bytes 32 8); (nelisp-native-load--make-scratch-vector A); drop every Lisp reference except the raw slot A (store A only in a second raw buffer C); run allocation churn plus (garbage-collect); then call the nl_vector_slot_ptr stub on ADDR or read (ptr-read-u64 A 8) and dereference it; expect use-after-free if the box is arena-managed.

* Decision (coordinator, 2026-11-03)

** lisp/nelisp-native-load.el:773 nelisp-native-load-box (string arm): REPRODUCED, FIXED
- Probe: tools/ai/rawptr-gc-probe.sh.
- On origin/main ee06ee849, 184 of 200 strings boxed into raw cells come back wrong with no explicit GC (mid-form GC at while back-edges), and 200 of 200 after garbage-collect.
- With (nelisp--debug-switch 6), which turns off mid-form GC, the first count drops to 0. So the probe reads the strings correctly, and the loss comes from the GC. Evidence: tools/ai/evidence/rawptr-probe-negative-control-20261103.txt.
- Fix: nelisp-native-load--slot-pins maps a slot address to its payload address, held as a Lisp integer. The GC pins integer-held arena blocks (0a304e554).
- The pin is dropped whenever the slot is rewritten (nelisp-native-load--zero-slot), and for each scratch cell once nl_vector_set_slot has copied it.
- Gate: standalone-reader-native-load-slot-pin-smoke, with a gate-mutation row.

** lisp/nelisp-native-load.el:857 nelisp-native-load--make-scratch-vector: NOT REPRODUCED
- 50 scratch vectors were checked before and after garbage-collect plus churn. Their box words and slot words were identical on origin/main.
- The probe did not establish why the box survives. It may be outside the swept arena or held through another path. The probe also has not shown that it would detect a freed box, so this verdict is "not reproduced", not "proven safe".
- No change was made for this site.
