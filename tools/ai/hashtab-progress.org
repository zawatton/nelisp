#+TITLE: Hash tables: GNU 31.1 struct Lisp_Hash_Table storage in the runtime

# User decision 2026-10-21: fix the representation first, imitating GNU.
#
# The eqhash lane (eval/eqhash-20261021, 50% of 4) made lookups flat in N:
# a string-key miss at N=8000 went from 414 to 78 us. Wall-clock own cost
# against GNU is still far off:
# - gethash hit: 7.1-11.5x;
# - gethash miss: 12.3-17.4x;
# - puthash: 302-358x.
# Entries are still stored in conses, and capacity is managed in Lisp.
#
# GNU 31.1 fns.c struct Lisp_Hash_Table:
# - key_and_value is one vector of pairs, plus the hash, next and index
#   vectors;
# - maybe_resize_hash_table grows the vectors in place;
# - hash_lookup and hash_put walk the index and next chains with no
#   allocation per entry;
# - sweep_weak_table handles weak tables.
#
# Start from eqhash's identity hashing and fixture: eval/eqhash-20261021 and
# its target/eqhash evidence. Its weak-table semantics (S1.2) depend on
# gc-port's conservative-root work and stay so here.
#
# Base: eval/integ-20261021w (eval/core 7d2d49fa3 plus the word-heap line,
# in final checks). Merge eqhash's branch first and resolve it on the word
# heap.
#
# Bar: wall-clock own cost against GNU 31.1, as paired per-round ratios on
# CPU 15 (COMMON.md Measurement).
