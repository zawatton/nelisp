#+TITLE: Native compiler: reject unbound free variables at build time, as GNU's byte compiler flags them

# Root cause of the word-heap S4.2 SIGSEGV (wh-s4f 7181d1cfd): a misplaced
# paren left `word` unbound in bf_env_capture_roots_w. The native
# compiler silently lowered the unbound symbol to a dynamic lookup through

* S1 Mechanism
** S1.1 A native function body with an unbound free variable fails the standalone build with a message naming the variable and the function
#+NOTE: 2026-10-21: Adapted GNU Emacs 31.1 bytecomp.el:3845-3876: after lexical lookup misses, accept boundp or the compile-unit declaration list. NeLisp reuses --special-vars and reports :free-symbol and :function before hidden-slot lowering. The brief requires an error instead of GNU's warning because native runtime helpers have no initialized dynamic boundary. The unchanged compiler accepted the bad object fixture; target/free-symbol/base-reject.json records its source and artifact hashes.
Declared specials (defvar/defconst/known runtime globals) still compile. A fixture shows both, and a control shows the base build accepts the bad case.
