# 4x is needed. Per call, NeLisp bytecode costs about 2,838 Ir against

#   evaluated as source text, not as byte-code objects.

* S1 Loader
** S1.1 A corpus of GNU 31.1 .elc files loads on dynamic and static and behaves like its .el
The corpus is notes-65's mxlib and cc-*.elc, plus a pinned set compiled from repository vendor files. It covers:
- the ;ELC header;
- #@ docstrings;
- #$;
- #[...] function objects;
- top-level (byte-code ...);
- defalias, defvar and defconst forms.

Every probed function returns the same values as its .el source and as GNU 31.1.
cmd: python3 tools/ai/elc-load-check.py corpus
** S1.2 load, require and locate-library in the runtime honour load-suffixes and load-prefer-newer as GNU's openp does
This covers .elc preferred when listed first, .elc-only directories, and the newer file under load-prefer-newer. A rejected or incompatible .elc signals as GNU does.
cmd: python3 tools/ai/elc-load-check.py resolve
** S1.3 Capability: (featurep 'nelisp-elc-load) holds exactly when the runtime can load .elc
The library gates its locate-file byte-code rejection on it.
cmd: python3 tools/ai/elc-load-check.py capability

* S2 Speed
** S2.1 A call of the same function costs at least 3x less when loaded from .elc than from .el
The functions are the mxlib microbenches, a 6-element cl-loop and a dolist. The measure is four-layout mean Ir per call, GC included. The ratio is the predicted milestone; record the actual one.
cmd: python3 tools/ai/elc-load-check.py speed
