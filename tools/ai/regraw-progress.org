** S1.2 The raw-ness proof is conservative and checked: a value is promoted only when every definition is raw by construction; a test plants a Lisp reference into a would-be-promoted local and the compiler refuses it (negative control), and the stack maps (smap1) still describe every Lisp-reference slot (maps unchanged for reference slots)
#+NOTE: The proof is a forward dataflow over the IR (docstring above `--vm-reg-analyze' in lisp/nelisp-aot-compiler.el). Two tiers, stated plainly: a LET variable named in the opt-in list must be proven raw or unwrapped at every definition (strict); a PARAMETER named in the list is declared raw (the IR cannot see its callers) and is only checked against known references (allocations, root slots, undeclared Lisp-typed parameters, and values computed from them), so a 64-bit load into a declared parameter passes. The negative controls plant a reference into a declared parameter (refused), a word load into a let variable (refused), and a rebuilt shifted word (refused). Stack maps: smap1 is type-conservative (every live slot is in the map whether or not it was promoted), emission is unchanged, and the [stackmap] statistics line of the candidate and seed-state builds is identical.
