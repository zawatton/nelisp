#+TITLE: emacs-lib: no function reads the ec buffer layer when native buffers own

Objective (user, 2026-11-13): fix the doubled buffer representation.  The
buffer of record is the runtime `nelisp-buffer' (unification plan
handoff/nelisp-emacs-unification_plan_2026-11-03.md, decision 5.1).  On
feat/emacs-lib-import at 0e140cf2c every buffer constructor already returns
`nelisp-buffer', but 13 commands emacs-lib installs still read the
`nelisp-ec-buffer' layer and fail in any real buffer
(`nelisp-ec-no-current-buffer').  GNU implements all 13 in Lisp, so the
plan's criterion 3 prefers the genuine vendor file (paragraphs.el, fill.el,
indent.el, simple.el, emacs-lisp/lisp.el, font-lock.el) over a polyfill.
NeLisp core changes go to notes-d0 as patches (decision 5.1 item 5).

Read with (from the NeLisp repo root, after building target/nelisp and
`make -f mk/emacs-lib.mk build-nelisp-bootstrap'):
  NELISP_BIN=target/nelisp bin/progress-meter.sh --ledger tools/ai/emacs-lib-ec-leak-progress.org
(bin/progress-meter.sh lives in the Notes workspace.)
