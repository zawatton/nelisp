S5.2 evidence: cold standalone-reader builds with NELISP_STANDALONE_JOBS=1 and 4
Commit a55c521b0 plus the uncommitted S5 edits (tree reports -dirty). Linux x86_64, host Emacs 31.1.
Every build ran under `ulimit -v 8388608` via bin/heavy-run.sh; no child died (no exit 88, no allocation failure).
Each build used its own unit cache (NELISP_STANDALONE_UNIT_CACHE_DIR, empty at start) and
target/nelisp-vendor-bytecode was deleted first (that directory cannot be relocated by env).
Memory: tools/ai/ci-speed-evidence/run-measured.py samples the whole process tree every 5 s.

Output path and tree path are embedded in the BINARY itself:
  Binaries built in two worktrees of the same commit (.../ref and .../fresh) differ (6bf1d9... vs 6fe706...);
  strings shows the repo root, e.g. nelisp-standalone--backquote-file "<root>/vendor/emacs-lisp/emacs-lisp/backquote.el".
  A dirty tree adds "-dirty" to the version string, which also shifts layout. Compare binaries only for one commit,
  one root path and one clean/dirty state. (The output file name is not in the binary: j1 == j4.)
  CI always uses the same root, so this does not bite there.
