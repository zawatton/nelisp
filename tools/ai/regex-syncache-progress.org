#+TITLE: Regexp cache: key syntax-dependent patterns on table identity, as GNU does

# Proposal from notes-65 (2026-10-21), accepted by the coordinator.
#
# Problem. In lisp/nelisp-stdlib-regexp.el, nlre--compiled-pattern-slow and
# nlre--cache-entry-match-p recompute (nlre--syntax-signature TABLE), a
# map-char-table walk of the whole table, on EVERY cache hit of a
# syntax-dependent pattern (\s \S \w \W \b \B \< \> \_).
#
# Measured in the 9d5f4 library image:
# (string-match "\\`\\(\\sw\\|\\s_\\)*\\'" "unsigned_long") costs 37-92 ms
# per call, against 0.001 ms in GNU. With the signature stubbed to the
# table itself:
# - cc-fonts load went from 85 s to 17 s;
# - 1105 string-match calls went from 64 s to 3.8 s;
# - the S1.3 js phase went from 148 s to 70 s (one run).
#
# GNU 31.1:
# - search.c:222: a cache entry matches when cp->syntax_table is Qt or
#   BASE_EQ to the buffer's syntax table. That is identity, not content.
# - syntax.c:1293: Fmodify_syntax_entry calls clear_regexp_cache().
# - search.c:166: clear_regexp_cache drops every syntax-dependent entry,
#   because modifying one table can change others through inheritance.
#
# Base: eval/core-20261017 at 9d5f4a515. Lands on eval/core next to
# candidate 3.

* S1 Mechanism
** S1.1 Semantics match GNU 31.1 on a pinned fixture, on dynamic and static
#+NOTE: 2026-10-21: Studied GNU 31.1 search.c:164-169 (clear every syntax-dependent entry because inheritance), search.c:222-224 (table identity), and syntax.c:1285-1293 (successful modify-syntax-entry then clear). Adapt this to table identity plus a global generation, retaining NeLisp's conservative dependency classifier; GNU regex-emacs.c:2096-2101 marks hard-coded word/space classes. Hit cost changes from O(table entries plus ancestors) allocation/traversal to O(1) identity/integer comparisons. The runtime mutator is outside this lane's permitted file set, so the regexp module wraps the current public mutator, clearing after successful calls without modifying prelude/package files. Install on the first cache miss, with a reentrancy guard and lexical capture of the underlying callable, before any dependent entry is inserted. Preserve the provider's documentation when the documentation API exists (it is absent during early bootstrap); the adapter is variadic, so argument-list introspection reflects the adapter, while argument checking/errors/returns come from the captured provider.
#+NOTE: 2026-10-21: Base dynamic fixture exposed an existing boundary mismatch: after @ becomes punctuation, GNU still matches \\b@\\b on "@" at 0, while NeLisp returned nil. GNU regex-emacs.c:4972-4974 explicitly accepts either string edge unconditionally. Adopt that rule in :wordb and add parity corpus cases, including the inverse \\B and empty string. The unavailable full artifact REPL launcher failed with (excessive-lisp-nesting . 16000); the narrow standalone --repl remains usable for the same-process red/reload/green check.
#+NOTE: 2026-10-21: Syntax-run audit found the existing parser accepted explicit group numbers beginning with zero, allowing group 0 to overwrite the overall match span. GNU regex-emacs.c:2225-2229 rejects these with REG_BADPAT. Adopt that narrow parser validation and pin GNU error symbol/data for both ?0 and ?01; add case-fold=t plan parity coverage.
#+NOTE: 2026-10-21: GNU regex-emacs.c:1281-1288 limits reported registers to 255 and :2280-2283 / :2331-2332 omits capture opcodes above that limit. Preserve the parser's logical group numbering, emit groups above 255 as shy bodies, and bound the compiled capture vector to 256 slots. This also prevents allocation proportional to a sparse explicit group number. Pin compact GNU summaries at 255/256 and verify a large accepted number does not allocate a huge capture vector.
#+NOTE: 2026-10-21: Astra audit exposed a bootstrap difference from GNU data.c:1009-1010 / nadvice.el:536-537: raw nl-afset does not honor defalias-fset-function, so a provider's replacement defun can lose an installed adapter. Reproduced warm -> fset replacement -> mutation -> stale entry in the same REPL. Add an O(1) function-cell comparison for syntax-dependent hits, reinstall the wrapper and advance the generation on replacement, before validating the old entry. No table traversal or literal-hit check is added. The regression exercises raw provider replacement and subsequent mutation. Library-owned mutation validation remains out of scope (the bootstrap currently accepts negative character keys); the failed-mutation test uses a non-string descriptor rejected by both implementations.
#+NOTE: 2026-10-21: Follow-up Astra audit found explicit group numbers also need GNU regex-emacs.c:2233-2235 signed-int overflow rejection before the capped capture allocation; :855 maps REG_ESIZE to (invalid-regexp "Regular expression too big"). Adapt the per-digit INT_MAX bound check and pin an above-bound input, without probing the potentially allocation-heavy maximum accepted group number.
The fixture covers:
- syntax-dependent matches before and after modify-syntax-entry, with the clear call made where GNU's modify-syntax-entry makes it;
- switching syntax tables between calls;
- a child table whose parent is modified;
- a non-syntax pattern that must stay cached across a clear.

** S1.2 A cache hit of a syntax-dependent pattern costs no more than twice the same-shape non-syntax pattern
#+NOTE: 2026-10-21: Stable full-match measurement after the cache change alone remains red: 50,500,332.125 / 2,870,922.625 Ir per call (17.590x), against base 51,477,469.875 / 2,870,998.625 (17.930x). Keep the full hot string-match gate and its 2x cap; lookup-only timing is diagnostic, not acceptance. GNU regex-emacs.c:5175-5200 reads live syntax for syntaxspec, and :4593-4628 writes capture registers directly. Adapt that execution mechanism with a general anchored greedy single-character syntax-union run plan, classifying once per input character and recording the final repeated capture without recursive group/backtracking allocation. Retain the generic matcher for unsupported shapes and max-end constraints; do not cache table-derived classifications, so direct table edits remain visible. GNU executes these operations in its bytecode VM; NeLisp currently feeds an AST to the Lisp matcher, and this lane excludes the native engine/binding layer. The adaptation stores an AST-derived plan and uses the same live-classification and register-write operations, rather than adding a native or changing that VM boundary. Predicted cost removes repeated group/rest/sentinel construction; the unchanged full-match gate will determine whether the cap is reached.
