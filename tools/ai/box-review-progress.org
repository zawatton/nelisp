#+TITLE: Word transport, transport only (heap object layout unchanged): retire 32-byte transport boxes

# Design, rooting rule and coexistence ABI: docs/design/215-word-transport-migration.org
#
# Reading: every runtime function passes and returns 64-bit tagged WORDs;
# 32-byte boxes that only carry a value between functions go away.  Cons,
# string, vector and record objects keep their layout.  wf_bytecode_* is out
# of scope until eval/bytecode-20261018 merges; m5_fx_* / nl_fx_* belong to
# the eval-s2s3 lane.
#
# Progress is the census (tools/ai/box-census.py) plus this meter.
#
# Env:
#   BOX_BIN         dynamic build under test
#   BOX_BASE_BIN    dynamic build of e0ab2ae3a
#   BOX_STATIC_BIN  static build of the same source as BOX_BIN
# Files written by hand after each build (never by the meter):
#   target/boxreview/census-current.tsv  NELISP_BOX_CENSUS output of the BOX_BIN build
#   target/boxreview/rec-current.json    box-callgrind.py record "$BOX_BIN"
#   target/boxreview/rec-base.json       box-callgrind.py record "$BOX_BASE_BIN",
#                                        recorded in the same batch as rec-current
#
# Baselines (GC-normalised windows, recorded together 2026-10-18):
#   base e0ab2ae3a  re 26422 allocs 47.34M Ir/match; call 89.9 / 166.8k; loop 21.0 / 54.4k
#   census baseline (31e5395ce + census hook, 114 units, 2786 defuns): 1977 debt
#   sites; stage-1 families gc 3, binders 89, regexp 123, evaluator 1198;
#   cons accessors in stage 1: 337.
# Instruction counts move with wall-clock-dependent polling under valgrind,
# so instruction criteria compare two records made in the same batch.
