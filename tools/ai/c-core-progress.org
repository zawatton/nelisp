#+TITLE: nelisp-emacs-lib -- GNU Emacs C-core coverage in NeLisp Lisp

Objective (user, 2026-09-30): implement every GNU Emacs 31.1 C primitive for the
NeLisp runtime in Lisp (nelisp-emacs-lib), keeping native implementations to the
bare minimum.  Areas and the missing set come from tools/c-core-coverage.sh
(regenerate: `tools/c-core-coverage.sh regen`, ~1 min; checks read its fresh
output and fail when it is older than the bundle or the binary).  Baseline
2026-09-30: 786/1460 bound after bootstrap; missing x-gui 31, display 213,
process 136, buffer 77, chars 54, files 43, other 120.

"Bound" is not "equivalent": each area also needs a host ERT file and an
end-to-end parity smoke that runs the standalone after the bundle loads and
diffs against host `emacs --batch` (GNU 31.1).  Batch semantics are the
reference for display/GUI functions (what GNU returns with no window system).

Units: implementations live in packages/nelisp-emacs-*/src/emacs-cc-*.el;
the Doc 211 bootstrap source-root flattens package sources and bundles the
C-core units in name order.  Probes live in
test/nelisp-emacs-lib/c-core-probes/*.el as (NAME FORM...) entries.
C?.2 is the static unit contract (test/nelisp-emacs-lib/c-core-units-test.el: guarded, in the
area table, not an empty stub).  C?.3 validates the recorded result of
`sh test/nelisp-emacs-lib/c-core-parity-smoke.sh run` (host vs standalone after the bundle;
every area name probed, no differing line) and fails when that result is
older than the bundle, binary, driver, area table or any probe file.
Every C?.3 and C8.3 also requires a complete 1460-name census, one area
owner and at least one canonical probe per census name.  The currently
incomplete inventory remains a failing check until those names and probes
are actually provided; a bound function alone does not satisfy parity.
