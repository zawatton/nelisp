#+TITLE: NeLisp GNU-bytecode interpreter on 64-bit words
#+NOTE: Objective (coordinator, 2026-10-18): the native GNU-bytecode
#+NOTE: interpreter (wf_bytecode_* in scripts/nelisp-standalone-build.el)
#+NOTE: keeps its operand stack and locals as 64-bit WORDs in a GC-traced
#+NOTE: vector frame, as the word VM (m5_fx_run_body) does: immediates are
#+NOTE: never boxed, heap objects are pointer words, common opcodes have word
#+NOTE: fast paths, GNU semantics are unchanged.  User decision (relayed
#+NOTE: 2026-10-18): all runtime transport moves from 32-byte boxes to words;
#+NOTE: the interpreter must hold no (alloc-bytes 32 8) scratch and call no
#+NOTE: box-view materializer; nl_val_store_word / nl_sci_store_imm only at
#+NOTE: boundaries with still-boxed callees.
#+NOTE: Baseline at e0ab2ae3a (tools/ai/bytecode-word-baseline.txt): loop of
#+NOTE: 1e6 0.143 s, bytecode call 1.75 us per caller-loop iteration (handoff
#+NOTE: measured 2.37 us), regexp match 4,220 us, corpus 145/145, audit 138.
#+NOTE: EVAL_BIN is a dynamic build of this tree; STATIC_BIN the static
#+NOTE: build (same command without NELISP_READER_DYNAMIC).  Benches run one
#+NOTE: at a time on a quiet machine.
