#+TITLE: Integer-held alloc-bytes buffers survive garbage collection

# Run from the repository root with a standalone binary built from this tree:
#   NELISP_BIN=target/nelisp BASE_BIN=<binary built from e05068412> \
#     bin/progress-meter.sh --ledger tools/ai/gc-int-pin-progress.org
# (bin/progress-meter.sh lives in the Notes workspace.)
#
# Defect (2026-11-02): `alloc-bytes' returns a buffer as a plain integer
# address, and the collector never treated an integer as a reference.  A
# collection that ran while the integer was still in use (mid-form at a
# `while' back-edge, or `garbage-collect') freed the block and wrote the
# free-list link into its first word.  `nl-ffi-loader--cstring's path
# buffer lost "/home/ma" before openat, so a real file read as ENOENT; CI's
# smoke job hit it in ffi-loader after caf7477e7 moved the layout.
# Mid-form GC off: no failures; on: failures (stress probe, measured).

* S1 The defect is reproduced by permanent checks

** S1.1 The int-root fixture fails on the pre-fix binary (negative control)
#+REQUIRES: BASE_BIN
cmd: ! "$BASE_BIN" --load test/standalone-alloc-bytes-int-root-smoke.el 2>&1 | grep -q 'alloc-bytes-int-root: PASS'

** S1.2 The ffi-loader stress probe fails on the pre-fix binary (negative control)
#+REQUIRES: BASE_BIN
#+TIMEOUT: 600
cmd: ! sh tools/ai/gc-int-pin-ffi-stress.sh "$BASE_BIN" 1 >/dev/null 2>&1
