#+TITLE: nelisp-emacs-lib — "make it usable" progress ledger

Machine-checkable progress for the objective "make nelisp-emacs-lib usable":
a pure-Elisp library that implements GNU Emacs's C-core behavior (buffer,
window, keymap, minibuffer, file/process I/O, redisplay, ...) so it runs on
the NeLisp runtime and can carry real vendor packages (magit, org, ...) and
the nemacs standalone/TUI editor as consumers. Read with:

  bin/progress-meter.sh --ledger dev/nelisp-emacs-lib/tools/ai/usable-progress.org --json

Repo identification (see worklog for the full trail): the user's path
"nelisp's packages/nelisp-emacs-lib" does not exist — dev/nelisp/packages/
holds small, unrelated nelisp-* utility packages (base64, sqlite, tramp,
...), none named emacs-lib. dev/nelisp-emacs-lib is a separate top-level
repo (origin: github.com/zawatton/nelisp-emacs-lib) whose own README.org
and AGENTS.md/CLAUDE.md describe exactly the target: "a reusable library
set that implements Emacs-compatible core behavior in Elisp for the NeLisp
runtime" (README.org, "Status" section), with nemacs-next, GUI/TUI, and
nelisp itself as consumers. There is no vendored copy of it under
dev/nelisp/packages/, so this is the single canonical source and this
ledger lives inside it, per instruction, at tools/ai/usable-progress.org
(this repo's tools/ already holds ad hoc scripts; ai/ is a new
subdirectory for this and future machine-checkable artifacts).

Stages follow the repo's own Doc 11 lane model (A Product-critical editor,
C Compatibility, D Display/runtime, E Operations) and Doc 27's library-gate
framing, mapped onto the 7-stage shape requested: build/bootstrap, C-core
symbol coverage vs GNU Emacs (via the repo's own nemacs-feature-coverage
sweep, host Emacs vs the standalone), buffer/editing core, file/process/IO,
real vendor package loading (magit), interactive nemacs usability, and
performance/stability gates. Checks prefer existing scripts/Makefile
targets and existing generated reports over new ad hoc probes. Where a
criterion needs a baked runtime image (build/nemacs-runtime.nlri or
build/nemacs-magit-runtime.nlri) that this checkout has not built — baking
is a multi-minute step out of scope for this ledger run — the check probes
for the image file first and fails fast instead of triggering a rebuild;
that is a true, currently-red "not yet usable" fact, not a skip.

NELISP_BIN should point at a built NeLisp standalone binary. This repo
vendors its own pinned copy at vendor/nelisp (default NELISP_ROOT), so
NELISP_BIN=<repo>/vendor/nelisp/target/nelisp works without touching
dev/nelisp.
