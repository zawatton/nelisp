#+TITLE: Native compiler code quality: GCC -O2 parity for the inner loops that NeLisp's runtime is written in

# Why. NeLisp's runtime (regex engine, evaluator, allocator, string and
# buffer primitives) is written in its own low-level dialect and compiled
# by NeLisp's native compiler. GNU's equivalents are C compiled by GCC.
# Both GNU-comparison studies trace a large share of the remaining gap to
# the generated code:
# - Doc 218 (regex): the per-character skip loop costs 159.26 Ir against
#   GNU's 6.99; one backtrack failure costs 1,464 against 178; tagged
#   access and conversion add about 12,000 Ir on heavy items.
# - Doc 219 (call path): even with candidates C1-C4, funcall stays at
#   9-11x GNU, and the plan's C4 is a general-compiler budget.
#
# The user's direction (2026-10-21) is to imitate GNU rather than tune.
# For compiled runtime code, the GNU reference is what GCC -O2 produces for
# the same loop structure.
#
# Base: eval/core-20261017 at 9d5f4a515. Implementer: Claude Opus 5.5.
#
# Bar: for each kernel below, NeLisp's native code takes no more
# wall-clock time per iteration than the same loop written in C and
# compiled with gcc 14.2 -O2 (the median of 7 alternating runs, pinned to
# the lane's CPU 9, warmed up, each run at least about 0.5 s; the loop is
# isolated by subtracting a zero-iteration run).  Callgrind Ir per
# iteration (four layouts) stays the diagnostic for where time goes.
#
# 2026-10-21 16:30, user: acceptance switched from Ir to wall-clock
# ("実時間での GNU 比較に切り替えて", COMMON.md "Measurement").  S1.1-S1.5
# and S2.1 were rewritten one for one from their Ir forms
# (`codegen-check.py kernel NAME' and an Ir end-to-end comparison).
