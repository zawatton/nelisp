* S1 Version identity
** S1.1 `--version` on dynamic and static
Each prints exactly one line, `NeLisp <describe> (<target>, <linkage>)`, where <describe> equals `git describe --tags --long --always --dirty` of the build source. It exits 0 with empty stderr and loads no user files. A control shows VER_OLD fails this check.
cmd: python3 tools/ai/version-check.py cli
** S1.2 Runtime identity: at runtime `nelisp-version` and `nelisp--cli-version` are bound to the same <describe> string, and an artifact manifest written by the binary records :nelisp-version equal to it rather than "unknown"
cmd: python3 tools/ai/version-check.py runtime
** S1.3 Provenance controls
- A build with NELISP_VERSION=<override> reports the override.
- A build from a tree with an uncommitted change reports a -dirty suffix.
- A build outside git, from an exported tree, reports the override or "unknown-<sha>". If none is derivable it reports "unknown", never a stale value.
cmd: python3 tools/ai/version-check.py controls
