#+TITLE: nl-ns — namespace boundaries as a checkable declaration

* Motivation

Doc 169 language defect #6: Emacs Lisp has no namespaces.  There is one
obarray, so =(defun foo ...)= is assignment to a global name and a
second definition silently wins.  Doc 168 sent the fix to Doc 90
because a real namespace system is an L3 change — it touches how the
reader turns text into symbols, which is the highest-cost, hardest-to-
withdraw layer in the whole design.

This package takes the other road.  It does *not* rewrite code, and it
adds nothing at run time.  It reads files and reports where the
boundaries that Elisp cannot enforce have actually been crossed.

** The cl-loop failure this is meant to catch

On August 15, 2026 the motivating bug was not "two files in this tree
define the same name".  It was "a file in this tree replaced a host
definition with one its own docstring already admitted was partial".

The concrete chain was:

1. =emacs-redisplay-realize-face= returned =nil=.
2. That led to =emacs-redisplay--face-resolve-spec= returning =nil=.
3. Its plist branch looked satisfiable, but the body was a =cl-loop=.
4. The =cl-loop= form returned =nil= in-tree but not in a real Emacs.
5. The in-tree =cl-loop= was a stub whose own warning said it was
   "minimal" and "returns nil" for forms it does not recognise.
6. =cl-lib.el= in the tree shadowed the host library, so =(require
   'cl-lib)= never loaded the genuine implementation.
7. The shim guard was a hand-written predicate that treated an
   autoloaded real definition as absent and clobbered it.

Every link in that chain is statically visible, which is why nl-ns now
reports it directly instead of making a human walk it with probes.

** Why not a renaming macro

The obvious library shape is =names.el='s: a =(define-namespace foo- ...)=
block that turns =bar= into =foo-bar= during macro expansion.  It buys
shorter source names and pays for them everywhere else — the debugger,
the backtrace, =describe-function=, =M-.=, and byte-compiler warnings
all start naming something the author never typed.  In a runtime whose
failures are already dominated by *silent wrong values*, adding a layer
that makes error messages disagree with the source is a bad trade.

And shorter names are not the problem.  The problems are:

1. collisions are silent,
2. "this file depends on that file" is written nowhere,
3. the =--= private convention is a comment, not a rule.

All three are checkable without touching a single source file.

* Findings

Same plist shape as =nl-check=: =(:kind KIND :subject S ...)=.

| kind                       | meaning                                     |
|----------------------------+---------------------------------------------|
| =ns-partial-override=      | partial shim can replace a host definition  |
| =ns-unsafe-shim-guard=     | host shadow behind a non-=fboundp= guard    |
| =ns-file-shadows-library=  | file basename masks a host library          |
| =ns-collision=             | symbol defined in more than one file        |
| =ns-collision-divergent=   | collision whose definitions differ          |
| =ns-prefix-violation=      | definition outside its file's namespace     |
| =ns-private-escape=        | another file's =--= name is referenced      |
| =ns-undeclared-dependency= | cross-file reference with no =require=      |
| =ns-shadows-host=          | tree definition also exists in host runtime |
| =ns-quoted-member=         | =nl-ns-in= leaves a member name as data     |
| =ns-unreadable=            | the file could not be read                  |

=ns-shadows-host= is the low-severity carrier: a tree definition whose
name also exists in the targeted host runtime.  That is not an error by
itself; shim modules do this on purpose.

=ns-partial-override= is the important one.  It fires when a host
shadow is also self-declared partial, based on the definition's
docstring and on the comment lines immediately above it.  The lexicon is
conservative and case-insensitive: =stub=, =minimal=, =subset=,
=partial=, =simplified=, =approximation=, =unsupported=, =returns nil=,
=does not handle=, =does not recognise= / =does not recognize=, =TODO=,
=FIXME=, and similar warnings.  The matched sentence is quoted into the
finding because the author already wrote the warning; nl-ns's job is to
put it where it will be read.

=ns-unsafe-shim-guard= fires when a host shadow is bare or hidden behind
a hand-written conditional instead of =(unless (fboundp 'name) ...)= (or
=boundp= for variables).  If the predicate text mentions =autoloadp=,
the report says so explicitly: an autoload is the real definition, not
evidence that the definition is absent.

=ns-file-shadows-library= is file-level, one finding per file.  It
reports the precondition that makes the above bugs invisible: when the
tree is on =load-path=, =cl-lib.el= or =seq.el= in the tree wins before
the genuine library can load.

* Host baseline

Host-shadow findings are deliberately opt-in.  nl-ns's analysis half
must keep running on =target/nelisp=, so it cannot ask the host runtime
questions while analysing.  Instead a host-only generator dumps a
readable baseline and the analyser reads that data back.

- The checked-in baseline is =baseline/emacs-30.2.el=.  It is a curated
  subset, not the generator's full output: the generator dumps every
  =fboundp= symbol of the host (9,153 functions on Emacs 30.2), while the
  checked-in file lists the seven functions, two variables and eight
  libraries the host-shadow findings are gated on.  Every entry was
  verified present on a real Emacs 30.2 (nix-emacs-ci's =emacs-30-2=, the
  same build CI installs) on 2026-09-19; =map= and =seq=, listed under
  =:functions= since 2026-08-16, were removed then because they are
  features, not functions, on any Emacs.
- =make baseline= writes the generator's FULL dump over that file.  Do not
  run it expecting the curated file back.  Widening the checked-in set to
  the full dump is a ratchet change -- measured 2026-09-19 against the
  30.2 dump, the gate reports 457 new gated findings (412
  =ns-unsafe-shim-guard=, 45 =ns-partial-override=) across 35 files -- and
  needs its own decision and its own acceptance work.
- The generator is =scripts/nl-ns-dump-baseline.el= and is meant to run
  under =emacs -Q --batch=.
- The baseline records the Emacs version, generation date, host
  functions, host variables, and library basenames reachable on
  =load-path=, including autoloaded definitions.

With no baseline, nl-ns emits none of =ns-partial-override=,
=ns-unsafe-shim-guard=, =ns-file-shadows-library=, or
=ns-shadows-host=.  No baseline never means guesses.

* Zero configuration

A file's namespace is *inferred*: the longest hyphen-boundary prefix
shared by more than half the names the file defines.

#+begin_src elisp
(nl-ns-file-namespace "a.el" '(nl-safe-one nl-safe-two nl-safe-three))
;; => "nl-safe-"
(nl-ns-file-namespace "prelude.el" '(car cdr princ terpri))
;; => nil   ; no dominant prefix
#+end_src

A file with no dominant prefix is treated as deliberately global and
skips the prefix check entirely, so a stdlib prelude that defines =car=
and =princ= does not drown the report.  =nl-ns-declare= overrides the
inference where it guesses wrong:

#+begin_src elisp
(nl-ns-declare "lisp/odd-one-out.el" "nelisp-")
#+end_src

Because inference needs no edits, the whole existing tree can be
analysed as it stands.

* Usage

#+begin_src elisp
(require 'nl-ns)

(let ((baseline "packages/nl-ns/baseline/emacs-30.2.el")
      (paths (file-expand-wildcards "lisp/*.el")))
  (let ((findings (nl-ns-check-files paths nil baseline)))
    (princ (nl-ns-report findings))
    (nl-ns-summary findings)))       ; => ((ns-collision . 12) ...)
#+end_src

Analysis and checking are separate from file I/O, so the pass also runs
on forms you already have:

#+begin_src elisp
(nl-ns-check
 (nl-ns-analyse '(("a.el" (defun eql (a b) a))
                  ("b.el" (defalias 'eql 'equal)))))
;; => ((:kind ns-collision :subject eql :files ("a.el" "b.el") :count 2))
#+end_src

The report header says which baseline was used and prints a one-line
severity summary first, for example =severity 1=1 2=1 3=1 6=1=.  That is
intentional: on a noisy tree, the first question is not "how many
findings exist?" but "is there anything in severities 1-3 at all?".

* Severity and gating

Each finding kind has a fixed severity, and the report is sorted by it:

| severity | kinds |
|----------+-------|
|        1 | =ns-partial-override= |
|        2 | =ns-unsafe-shim-guard= |
|        3 | =ns-file-shadows-library= |
|        4 | =ns-collision-divergent= |
|        5 | =ns-private-escape=, =ns-prefix-violation=, =ns-undeclared-dependency= |
|        6 | =ns-collision=, =ns-shadows-host=, =ns-quoted-member=, =ns-unreadable= |

=nl-ns-report-max-severity= returns the highest-priority severity present
or 0 for a clean run.  A build gate can therefore fail on severities
1-3 only without treating every benign shim as an error.

* What it finds in this tree today

Over =lisp/=, =src/=, =scripts/= and =packages/*/src/= (340 files):

| kind                  | count |
|-----------------------+-------|
| =ns-prefix-violation= |   808 |
| =ns-private-escape=   |   520 |
| =ns-collision=        |   306 |
| =ns-collision-divergent= | 1 |

The collisions are dominated by the two-stdlib split — =abs=, =and=,
=append=, =backquote=, =eql= and 300 others exist once in
=lisp/nelisp-stdlib*.el= and again in =scripts/nelisp-stdlib-prelude.el=,
with no mechanism anywhere that says the two must agree.  =eql= is the
case where they already do not: one file aliases it to =equal=, the
other gives it the numeric-aware definition.

=ns-collision= and =ns-collision-divergent= partition collisions: a
divergent finding replaces, rather than accompanies, the plain
collision for its symbol.  Definitions are compared as read forms,
ignoring only the definition's own docstring.  Whitespace, indentation,
comments, and docstring wording therefore do not make a collision
divergent.

The private escapes are concentrated in the AOT compiler reaching
through the assemblers' =--= boundary
(=nelisp-asm-arm64--emit-word=, =nelisp-asm-x86_64--abi-win64-arg-regs=,
=nelisp-asm-wasm--global-kind=, ...), which is why those modules cannot
be refactored independently today.

* CI gate

=make ns-inventory= counts the findings and fails when any kind exceeds
=tools/ns-inventory-baseline.txt=.  Same ratchet rule as
=make unsafe-inventory=: below the baseline prints a notice so the
number can be lowered in the change that shrank it; above it fails.
The point is to stop the numbers growing, not to demand a cleanup
nobody scheduled.

=ns-undeclared-dependency= is not part of the gate.  A tree that has
always relied on load order produces one finding per edge of its real
dependency graph — worth reading once, useless as a threshold.  Pass a
non-nil second argument to =nl-ns-check= to see it.

For host-shadow findings, use =nl-ns-report-max-severity=: it lets a
gate fail on =ns-partial-override=, =ns-unsafe-shim-guard=, and
=ns-file-shadows-library= while leaving plain =ns-shadows-host= as
informational noise.

* Limits

- *Reference collection is over-approximate.*  Every symbol in a form
  counts as a reference, including quoted data.  That is deliberate:
  this codebase passes function names as quoted symbols constantly, and
  missing those would understate the coupling.
- *Only cross-file ownership is modelled.*  Defining a name twice in
  one file is a different problem and is not reported here.
- *A symbol defined in two files has no single owner*, so no private
  escape is attributed to it; the collision finding covers it instead.
- *Nothing is enforced at run time.*  This package cannot prevent a
  collision, only report one.

* Non-goals

- *Not a renaming layer.*  See above.
- *Not a module system.*  There is no import form, no export list, no
  visibility enforcement — only a report on the conventions already in
  the source.
- *Not depended on by anything.*  Like =nl-check= (Doc 168 section 4.1),
  the arrow points one way so the package can always be deleted.

* Writing inside a namespace

=nl-ns-in.el= is the optional writing half of this package.  It turns
the short names in a block into ordinary qualified global names; it does
not replace the checker in =nl-ns.el=.

#+begin_src elisp
(require 'nl-ns-in)
(nl-ns-define text :members (limit wrap chunk external-helper))
;; default prefix: "text-"

(nl-ns-in text
  (defvar limit 80)
  (defun wrap (s) (external-helper (chunk s limit)))
  (defun chunk (s n) (substring s 0 n)))
;; Defines text-limit, text-wrap, and text-chunk.
#+end_src

=nl-ns-define= declares a namespace, its closed =:members= set, and
optionally an explicit =:prefix=.  =nl-ns-in= rewrites and evaluates its body;
=nl-ns-expand= returns its rewritten forms for inspection or tests;
and =nl-ns-qualify= returns one qualified symbol.

The resolution rule is exact: a symbol is rewritten if and only if it
is in the declared member set.  Foreign names remain untouched.  A
definition whose name is not declared is an expansion-time error; this
catches a typo or an accidental extra definition instead of changing
the block's meaning.  A member need not be defined in every block: it
may refer to a definition from another block in the same namespace.

Likewise, a local binding may not use a member name.  =let=, =let*=,
=lambda=, definition argument lists, =dolist=, =dotimes=, and
=condition-case= all signal an expansion-time error naming the symbol
and asking you to rename the local.  There is no escape hatch: rename
the local so that a member always means the namespace member.

Quoted data is never rewritten: ='chunk= stays =chunk=.  A function
reference is different: =#'chunk= is rewritten to =#'text-chunk=.  The
literal part of a backquote template is also data, while unquote and
splice positions are evaluated and rewritten.  To make a template
expand into a call to a member, write the qualified name in the
template, or use =,(nl-ns-qualify 'text 'chunk)=.  The checker reports
=ns-quoted-member= for a declared member that appears in a quote or
backquote template inside an =nl-ns-in= block, so those places can be
made explicit.

Member names must now be written twice: once in =:members= and once at
their definition or use.  That is the price of order-independent macro
expansion, the same trade Common Lisp makes with =:export=.

This is only a convenient spelling for ordinary globals.  There is no
isolation: another file can still collide with =text-wrap=, which is
exactly what this package's checker half detects.  There is no privacy.
The debugger, backtrace, and =M-.= show qualified names, because those
are the real global names.
