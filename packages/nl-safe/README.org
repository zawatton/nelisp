#+TITLE: nl-safe — dynamic borrow cells and fat pointers for NeLisp

* Motivation

Doc 170 Stage 1.  NeLisp's ordinary Lisp layer is already memory-safe
(it is a GC'd dynamic language); the danger lives in the *runtime
implementation layer*: raw pointers, =syscall-direct=, arenas, mmap
regions.  =nl-safe= gives that layer Rust-style discipline in three
pieces:

1. *Aliasing safety* — =nl-cell= borrow cells enforce
   "sharing XOR mutation" with runtime counters (the =RefCell=
   strategy: dynamic checks first, static checks later, Doc 168
   section 3.2).
2. *Memory safety* — fat pointers =[nl--ptr BASE LEN GENERATION]=
   bounds-check every access and detect use-after-free through
   allocation generations.
3. *An unsafe boundary* — the only places allowed to mint raw
   pointers are =nl-unsafe= blocks, and the unsafe-primitive
   inventory is a named, CI-capped list (<= 20 entries).

This is an *opt-in* extension library (Doc 168 section 2): loading it
changes nothing about plain Elisp semantics.  It depends only on
=nl-prelude= (error hierarchy, =nl-strict=).

* Borrow cells

#+begin_src elisp
(nl-defcell buf (make-vector 1024 0))

(nl-with-borrow (b buf)          ; shared borrow, any number may coexist
  (aref b 0))

(nl-with-borrow-mut (b buf)      ; exclusive borrow
  (aset b 0 42))
#+end_src

- Representation: =[nl--cell VALUE STATE]= with STATE = 0 free,
  n > 0 shared borrows, -1 exclusive.
- =nl-with-borrow= signals =nl-borrow-error= when the cell is
  exclusively borrowed; =nl-with-borrow-mut= signals unless the cell
  is completely free.  A failed acquire changes no state.
- The borrow is released by =unwind-protect=, so STATE is restored on
  =signal= and =throw= as well as on normal exit.
- =nl-cell= constructs an anonymous cell; =nl-cell-p= tests for one.

Concurrency note: the =clone(2)= shared-address-space path needs
atomic STATE updates (Doc 170 section 3.4) — not wired yet, see
Follow-ups.

* Violation log (Doc 168 Phase 6 gate data source)

Set =nl-safe-log-violations= non-nil and every violation (borrow,
bounds, generation) is also pushed onto =nl-safe--violation-log=,
newest first, as a plist:

#+begin_src elisp
(:kind borrow     :cell NAME :existing shared|exclusive
 :existing-shared-count N :requested shared|exclusive)
(:kind bounds     :op OP :offset O :size S :len L)
(:kind generation :op OP :expected G :actual A)
#+end_src

The Phase 6 go/no-go decision (build a static checker only if > 50%
of dynamically caught violations were statically decidable) reads
this log, so records deliberately keep the full context the call site
has.

* Phase 6 gate data collection

=nl-safe-report.el= plus the repo-root =make alloc-check-collect=
target are the wiring that feeds the Doc 168 Phase 6 gate ("start
static checking only if > 50% of dynamically caught violations are
statically decidable").  The flow:

1. *Collect (nl-safe side)* — enable =nl-safe-log-violations= in dev
   sessions, then dump the accumulated log to a file:

   #+begin_src elisp
   (require 'nl-safe-report)
   (setq nl-safe-log-violations t)
   ;; ... work; violations accumulate in nl-safe--violation-log ...
   (nl-safe-report-dump "~/nl-safe-violations.log" t)  ; append + clear
   #+end_src

   One printable sexp per line, oldest first, append mode — safe to
   dump into the same file across many sessions.  Each record gets a
   =:static unknown= placeholder field.  =nl-safe-report-clear=
   empties the in-process log without dumping.

2. *Collect (allocator side)* — from the repo root:

   #+begin_src sh
   make alloc-check-collect NELISP_STANDALONE_TARGET=windows-x86_64
   #+end_src

   runs the checked-allocator workloads (the
   =standalone-reader-checked= stress script, a heavier churn script,
   and a full stdlib-prelude load) with =NELISP_ALLOC_CHECK=1= and
   appends one =<UTC timestamp> <workload>
   <(nelisp--alloc-check-report)>= line per workload to
   =.alloc-check/reports.log=.  The directory is gitignored — the
   data stays local, like =.anvil-worklog=.  A prebuilt
   =target/nelisp[.exe]= is used as-is; nothing is rebuilt.

3. *Classify* — a human edits the dump file, flipping each record's
   =:static unknown= to =yes= (a static checker could have caught it)
   or =no=.

4. *Decide* — summarize and read the numbers:

   #+begin_src elisp
   (nl-safe-report-summarize-file "~/nl-safe-violations.log")
   ;; => (:total N :by-kind ((borrow . …) …) :by-cell ((buf . …) …)
   ;;     :static (:yes Y :no N :unknown U))
   #+end_src

   If yes / (yes + no) exceeds 50% (with unknowns driven down far
   enough to trust the ratio), Phase 6 (=nl-check= static linearity
   checking) is a go; otherwise it is dropped (Doc 168 section 5).

All report functions run unchanged on host Emacs and on the
standalone binary (file I/O dispatches between =write-region= /
=insert-file-contents= and the standalone's =wrf= / =rdf= builtins).

* Fat pointers

#+begin_src elisp
(nl-unsafe
  (setq p (nl-ptr-make base len generation)))  ; [nl--ptr BASE LEN GEN]

(nl-ptr-ref-u8  p 3)        ; bounds + generation checked
(nl-ptr-set-u8  p 3 255)
(nl-ptr-ref-u64 p 0)        ; little-endian
(nl-ptr-slice   p 4 8)      ; derived pointer, clamped to the parent
#+end_src

Every checked access enforces =0 <= OFFSET=, =0 <= SIZE=, and
=OFFSET + SIZE <= LEN= (=nl-ptr-bounds-error=), then compares the
pointer's GENERATION with the allocator's current one
(=nl-ptr-generation-error= — use-after-free detection).  A slice can
only narrow the range, never widen it, and inherits the parent's
generation, so freeing the parent invalidates every slice.

** Raw-memory backend (the integration point)

Host Emacs has no raw memory, so *all* actual memory access is routed
through the funcall'able =nl-safe-ptr-backend=:

| op           | args              | meaning                              |
|--------------+-------------------+--------------------------------------|
| =ref-u8=     | BASE OFFSET       | read one byte                        |
| =set-u8=     | BASE OFFSET VALUE | write one byte                       |
| =ref-u64=    | BASE OFFSET       | read little-endian u64               |
| =sub-base=   | BASE DELTA        | derived base for =nl-ptr-slice=      |
| =generation= | BASE              | current generation, nil = skip check |

The default backend is a pure-Lisp mock (vector-backed stores with a
generation counter and =nl-safe-mock-alloc= / =nl-safe-mock-free= /
=nl-safe-mock-ptr= helpers), which makes the whole checking layer
testable on host Emacs *and* on the standalone binary.  Wiring a real
backend onto the standalone's raw-memory primitives (=alloc-bytes=,
=ptr-read-u8=, =ptr-write-u8=, =ptr-read-u64=, pointer arithmetic,
allocator generations from the checked allocator of Doc 170
section 5) is follow-up work; this variable is the single seam.

* Unsafe boundary

=nl-ptr-make= is the package's only pointer-minting primitive.  Under
=(nl-strict t)= (nl-prelude's load-unit-scoped flag) using it outside
an =nl-unsafe= block is an *expansion-time* error:

#+begin_src elisp
(nl-strict t)

(nl-ptr-make raw len gen)          ; expansion error

(nl-unsafe
  (nl-ptr-make raw len gen))       ; allowed
#+end_src

=nl-safe-unsafe-primitives= is the named inventory of everything that
may mint or dereference raw memory (currently 15 entries; an ERT
asserts the <= 20 cap, Doc 170 section 4.3).  Only =nl-ptr-make= is
expansion-gated by this package: the rest are standalone runtime
primitives, and auditing *their* call sites (plus counting
=nl-unsafe= blocks in CI) is the =nl-check= inventory report's job
(Doc 170 section 10).

* Disabling the checks (Doc 170 section 9)

=nl-safe--enabled= (default t) is read at *macro-expansion time*.
When nil, =nl-with-borrow= / =nl-with-borrow-mut= expand to a plain
=let= over the cell value and the =nl-ptr-*= accessors expand to the
bare backend access — zero checking residue.  ERT compares these
expansions against the hand-written plain forms (expansion-identity
gate), which is what keeps "the flag can compile the checks away"
true.

Same caveat as =nl-strict=: the flag only affects expansions
performed after it flips — set it at top level
(=(eval-and-compile (setq nl-safe--enabled nil))=) or around an
explicit =eval= / =macroexpand=, never inside an already-expanded
body.

* Errors

| Symbol                    | Parent         | Signaled by                         |
|---------------------------+----------------+-------------------------------------|
| =nl-borrow-error=         | =nl-error=     | borrow rule violations              |
| =nl-ptr-error=            | =nl-error=     | (never directly — common parent)    |
| =nl-ptr-bounds-error=     | =nl-ptr-error= | out-of-range pointer access         |
| =nl-ptr-generation-error= | =nl-ptr-error= | stale generation (use-after-free)   |
| =nl-type-error=           | =nl-error=     | non-cell / non-pointer / bad byte   |

(=nl-type-error= is nl-prelude's.)

* Non-goals

- No static borrow checking — that is Doc 168 Phase 6, gated on the
  violation-log data this package collects.
- No resource / Drop tracking (=nl-defresource=) — Doc 170 Stage 3.
- No contracts — Doc 170 Stage 4 (=nl-contract=).
- No change to plain Elisp semantics; nothing is advised or globally
  modified.

* Resources and deterministic drop (Doc 170 Stage 3)

=src/nl-resource.el= adds the third safety axis of Doc 170 section 1:
*resource* safety.  Aliasing and memory are Stage 1's job; this is
about releasing exactly once.

#+begin_src elisp
(nl-defresource file-handle :drop (lambda (fd) (nl-close fd)))

(nl-with-resource (fd (nl-resource 'file-handle (nl-open path)))
  (nl-read (nl-resource-handle fd) 100))   ; released on scope exit
#+end_src

- Representation: =[nl--resource TYPE HANDLE LIVE]=.  LIVE goes nil the
  moment the value is consumed, which is what turns double-free and
  use-after-free in the runtime layer into a signaled
  =nl-resource-error= instead of silent corruption.
- =nl-drop= runs the drop function exactly once; a second call signals
  =nl-double-drop-error=.  =nl-resource-handle= on a consumed resource
  signals =nl-use-after-drop-error= — a stale fd or mmap address is
  precisely the value that corrupts quietly.
- The liveness flag is cleared *before* the drop function runs, so a
  releaser that signals still leaves the resource consumed rather than
  droppable again.
- =nl-with-resource= expands to =unwind-protect=, so the release also
  happens on =signal= and =throw=.  It skips the drop when the body
  already consumed the resource, so an explicit =nl-drop= inside the
  body is not a double free.
- =nl-with-resources= nests, releasing in reverse acquisition order.
- =nl-forget= is Rust's =mem::forget=: it consumes without releasing,
  for the case where ownership moved somewhere this library cannot
  see.  It is the one operation here that leaks on purpose.
- Constructing a resource of an unregistered type is refused up front
  (=nl-unknown-resource-error=): a resource nobody can release is a
  leak by construction.
- Violations land in =nl-safe--violation-log= with =:kind= =resource=,
  feeding the same Doc 168 Phase 6 gate as the Stage 1 kinds.

Static companion: =packages/nl-check= reports resources that are never
dropped, dropped twice on one path, or that left the checker's sight
(Doc 170 section 6.3).  It is a separate package on purpose — nothing
here depends on it.

* Testing

Host Emacs (part of =make test= at the repo root; the root Makefile
globs =packages/*/test/nl-*-test.el=):

#+begin_src sh
emacs --batch -Q -L packages/nl-prelude/src -L packages/nl-safe/src \
  -L packages/nl-safe/test \
  -l ert -l nl-safe-test -f ert-run-tests-batch-and-exit
#+end_src

Standalone NeLisp (no Emacs, no ert — a minimal shim runs the same
test bodies; dependencies are loaded by explicit path because the
standalone's =require= silently succeeds on missing files):

#+begin_src sh
./target/nelisp --load packages/nl-safe/test/nl-safe-standalone-smoke.el
./target/nelisp --load packages/nl-safe/test/nl-resource-standalone-smoke.el
#+end_src

Both smokes also run =examples/nl-safe/borrow-violation.el= via
=packages/nl-safe/test/nl-safe-example-test.el= (matches the
`packages/*/test/nl-*-test.el' glob, so it is also part of the
host-Emacs `ert-full' gate), so the "caught at the moment of
violation" example cannot silently rot.

* Portability claim, measured (2026-08-22, target/nelisp built from
  06ed9bd3a)

Every claim above about running "unchanged on host Emacs and on the
standalone binary" is TRUE, not just claimed:

- Host Emacs: 132/132 combined `nl-safe-test.el' +
  `nl-safe-report-test.el' ERT cases and 29/29 `nl-resource-test.el'
  cases pass (part of `ert-full').
- Standalone: `nl-safe-standalone-smoke.el' runs the identical
  `nl-safe'/`nl-safe-report' bodies plus the 3-case example suite --
  106/106 pass; `nl-resource-standalone-smoke.el' runs the identical
  `nl-resource' bodies -- 29/29 pass.  Both print `GATE-COUNT
  checked=N findings=0' and are gated as `nl-safe-standalone-smoke' /
  `nl-resource-standalone-smoke' in =tools/ai/gates.expected= /
  `nelisp-ai.sh extras'.

One claim above needed re-checking rather than trusting: "the
standalone's =require= silently succeeds on missing files" (used to
justify loading dependencies by explicit =load= path here and in the
smoke runners).  Measured directly against this =target/nelisp=
build: =(require 'totally-bogus-feature-xyz)= and =(require
'generator)= both now signal =(file-missing . FEATURE)= loudly rather
than succeeding silently.  Whatever produced the silent-success
behaviour this package's tests were written defensively around is not
reproducible here; the explicit-=load= style stays (it is correct
either way, and cheap), but the specific silent-success claim should
not be repeated as current fact without re-measuring against whatever
build is in hand.
