#+AUTHOR: Claude (design), zawatton (direction)
#+DATE: 2026-10-17
#+STATUS: IN PROGRESS (2026-10-17) — design and stage plan; S1 started.
#+NOTE: Progress is measured only by tools/ai/214-cl-threads-progress.org.

* §0 TL;DR

Doc 199 shipped real OS threads, but only as a linux-x86_64 primitive that
evaluates a pre-built form on a private context and hands back an integer.
The owner wants what an SBCL user gets: arbitrary closures on threads that
return arbitrary values, locks, condition variables, semaphores, per-thread
special bindings, global writes from any thread, and interrupt/destroy, on
both linux-x86_64 and windows-x86_64.

The API is a separate, bordeaux-threads-shaped namespace (=nl-bt-*=), not
Emacs's =make-thread= family.  Emacs's cooperative thread API keeps its
Emacs semantics, so Elisp written for Emacs is unaffected; code that wants
real parallelism opts in by calling =nl-bt-*=.

The core obstacle is not spawning a thread.  It is that the interpreter
keeps per-evaluation state in process-global slots: the signal/throw
stash, the GC frame ring, the Win64 extern-call rsp spill slot, the
backtrace snapshot.  §2 lists every item with its fix.

Dynamic =let= is deep binding on the context's private frame stack, so a
new thread already sees global values, not its parent's bindings —
exactly bordeaux-threads semantics.  No change is needed there.

* §2 Mechanism: the thread block

Every thread owns a /thread block/.  The main thread's block *is* the arena
base, so in a single-threaded run every stash address is unchanged and
behaviour is byte-identical.

- A new compiler IR op, =(thread-block)=, returns the current thread's block
  address:
  - windows-x86_64: =TlsAlloc= once at start-up; the index is kept in bss,
    and the op reads =gs:[0x1480 + idx*8]= (TEB TlsSlots; idx < 64 is
    asserted at start-up).
  - linux-x86_64: each thread calls =arch_prctl(ARCH_SET_FS, block)= once,
    with =block[0] = block=; the op reads =fs:[0]=.  The standalone runtime
    has no libc, so FS is otherwise unused.
- =nelisp-standalone--chunk-arena-rewrite= already turns every integer atom
  in the arena range into =(+ arena-base OFF)=.  For OFF in the per-thread
  range [16, 88) it now emits =(+ (thread-block) OFF)=.
- Data symbols that must be per-thread (the GC frame ring, the rsp spill
  slot, the backtrace snapshot) move to fixed offsets inside the block
  beyond 4096.  The main thread's block keeps its old bss storage through a
  block-relative indirection word at block+4096 + k*8.  The GC marks every
  registered thread's stash TAG/VAL, not only the collector's.

* §3 API (=packages/nelisp-bt=)

bordeaux-threads names, prefixed =nl-bt-=:
- =nl-bt-make-thread FN &key name initial-bindings=, =nl-bt-join-thread=
  (returns FN's value; re-signals its error), =nl-bt-current-thread=,
  =nl-bt-all-threads=, =nl-bt-thread-alive-p=, =nl-bt-thread-name=,
  =nl-bt-thread-yield=, =nl-bt-interrupt-thread=, =nl-bt-destroy-thread=.
- =nl-bt-make-lock=, =nl-bt-make-recursive-lock=, =nl-bt-acquire-lock= (with
  =:wait-p= / =:timeout=), =nl-bt-release-lock=, =nl-bt-with-lock-held=,
  =nl-bt-with-recursive-lock-held=.
- =nl-bt-make-condition-variable=, =nl-bt-condition-wait= (=:timeout=),
  =nl-bt-condition-notify=, =nl-bt-condition-broadcast=.
- =nl-bt-make-semaphore=, =nl-bt-signal-semaphore=, =nl-bt-wait-on-semaphore=.
- =nl-bt-atomic-integer=, compare-and-swap, and incf on it.

On host Emacs, the package maps onto Emacs threads (cooperative, correct,
no speedup), so the same code and ERT run on both.

* §4 Stages

- S1 Per-thread interpreter state (thread block, stash, frame ring, rsp
  spill slot).  Done when every existing standalone smoke stays green on
  windows and linux, and two linux workers signalling different errors
  concurrently each see their own error.
- S2 Windows spawn/join with private context.  Done when
  =nelisp-thread-standalone-smoke= and the allocating and percpu-roots
  smokes pass on windows-x86_64.
- S3 Closures and arbitrary values: =nelisp-thread-spawn= takes a function
  and returns its value or re-signals its error in the joiner.
- S4 Locks, condition variables, semaphores (linux futex, Windows
  WaitOnAddress/WakeByAddress).
- S5 Global writes and interning from any thread (mirror lock, intern lock).
- S6 Unbounded allocation and GC from any thread, without a bounded section.
- S7 Thread objects, interrupt and destroy at safepoints.
- S8 =packages/nelisp-bt= API, host ERT, standalone smokes on both targets, and a
  real parallel speed-up measured on Windows.

* §5 Results

- S0.2 baseline nelisp-unsupported-primitive: on main 6d759c79 the
  windows-x86_64 build (76 s) answers =(nelisp-thread-spawn 2 0 1 2 3)= with
  =nelisp-unsupported-primitive=.
- S1 (2026-10-17): thread blocks hold the signal/throw stash (193 TEB
  loads on Windows); the Win64 rsp spill slot is
  TlsSlots[nl_tls_rsp_index] (117 save/restore pairs); GC frame rings are
  per-thread.  A Linux eval worker owns its block at env+2048, its FS
  control block at env+3072 and its ring at env+1052672.
  =tools/nelisp-bt-stash-smoke.el= gives BT-STASH-FAIL on 6d759c79 and
  PASS 3/3 with the change.  On linux (WSL) the Doc 199 smokes pass; on
  windows the reader, process, TLS and nelisp-service smokes pass.  Two
  failures are unchanged from 6d759c79 and not caused by this work:
  - emacs-parity's single finding under WSL Emacs 30.1
  - windows =standalone-reader-test=: compile-runtime-image exit=1
  =nl_bt_snapshot= (backtrace diagnostics) is still process-global.
- S2 (2026-10-17): windows-x86_64 links the Doc 199 thread arms.  The
  OS-specific units become VirtualAlloc (worker mmap, shared memory,
  launch page) and CreateThread with a 64 MiB reserved stack; the entry
  installs the worker's thread block with TlsSetValue and returns.  Two
  fixes went beyond the port:
  - A section starts in a chunk with 64 MiB free, growing a 512 MiB
    chunk if needed.  Windows chunks are 64 MiB and the prelude nearly
    fills the first one, so =gc-inhibit 1= used to return -12.
  - Only the main thread starts a mid-form collection.  A worker's
    =while= back-edge requested a park it could never satisfy and
    missed after the bounded wait.  Once allocation debt was due it did
    that on every iteration, which looked like a hang after about 6000
    iterations.
  On Windows the four Doc 199 smokes pass (checked=6/9/13/14, parked=3)
  and nelisp-bt-stash-smoke passes 3/3 (38 s).  Linux is unchanged.
- S4 (2026-10-17): =packages/nelisp-bt= (native + emacs backends) on new
  primitives:
  - atomic cas/store
  - futex-style wait/wake: futex(2) on Linux; WaitOnAddress and
    WakeByAddress* on Windows, imported from
    api-ms-win-core-synch-l1-2-0.dll
  - whole-operation mutex lock/unlock: owner id and hold depth kept
    natively, adaptive spin, then 5 ms OS-wait slices with a park
    safepoint after each
  - condition wait/notify and semaphore wait
  Every interpreted call costs 20-60 µs, so moving each operation into one
  primitive and expanding =nl-bt-with-lock-held= to direct primitive
  calls took a worker's locked increment from ~1.1 ms to ~0.2 ms.  Three
  runtime defects showed up and were fixed:
  - A Windows bump allocation called VirtualAlloc for every object.
    Commits now go through a per-chunk watermark (descriptor +56) in 1 MiB
    steps; allocating code inside a section ran 3x slower before.
  - Park requests counted finished workers, so after the first worker
    finished every request was a guaranteed miss: the collector waited
    out its bound while the parked workers stood still.  Retired workers
    (=nl_thread_retired=) are now subtracted, and the count is re-read on
    every spin.  A 4x1000 contended run went from 10.2 s with 30 misses to
    1.9 s with 0.
  - Worker =while= back-edges are now park safepoints (=nl_gc_backedge=).
  Known S6 gap: once collections inside a section really ran, one 4-thread
  lock run in three crashed (SIGSEGV).  The main thread therefore starts no
  mid-form collection while a section is open, which matches the
  effective behaviour before (every request missed).  With that gate
  there were no crashes in 8 runs.
  =tools/nelisp-bt-sync-smoke.el=: lock 80000 (unlocked 48164-48868),
  condvar 500500, semaphore 1000 plus a timeout; 3/3 on windows (~31 s)
  and 3/3 on linux.
- S5 (2026-10-17): workers write globals.  Mirror values were already
  published as a fresh box behind one 8-byte store, so unlocked readers
  never see a torn value.  The 11 mirror write entry points, defvaralias
  and the special-variable registry now run under one recursive
  =nl_mirror_lock= instead of being refused.  The lock is skipped while
  no worker is registered.  Intern misses re-probe under
  =nl_intern_lock=, and an insert now publishes the name buffer before
  the length; hits stay lock-free.  Further fixes:
  - =lookup_function= copies the slot once, so a concurrent
    =fmakunbound= cannot hand back the unbound marker.
  - Registry slots are claimed atomically, so workers can spawn workers.
  - Walkers stop at 64 entries, and env 0 matches no entry.
  - nl-bt rebinds =nl-bt-thread-local-variables= in every thread: the
    regexp engine's match data, in-progress captures, parse counter and
    compile cache, plus =load-file-name=.  Sharing them corrupted
    concurrent =string-match= (args-out-of-range, nil captures).
  =tools/nelisp-bt-global-smoke.el= (8 threads) passes 3/3 on windows and
  passes on linux; on the S4 binary it is refused with
  nelisp-worker-mirror-mutation.  Each thread runs set, defalias, defvar
  and a per-thread match, and a locked global counter reaches 8000.
  40000 fresh interns are all found and 500 names interned concurrently
  are =eq= everywhere.  The Doc 199 mirror-guard smoke now asserts the
  new contract: the same 14 checks, with writes taking effect.
  Not yet serialised: =put=/=setplist= (one global plist hash table),
  =provide= and ordinary Lisp hash tables, all unsynchronised like
  SBCL's non-:synchronized tables.
- S6 (2026-10-18): collections inside a section are sound, and the arena
  grows there.  Each defect was found by a crash, and each fix was
  confirmed against it:
  - Parked workers' native stacks were never scanned.  A worker now
    records its stack top (env+2032) at start, and its rsp (env+2040) and
    callee-saved registers (env+1952, the new =save-callee-regs= IR op)
    when it parks.  The collector scans them, plus its own registers.
    The 4-thread lock run that crashed 1 in 3 crashed 0 in 10.
  - Waits allocated their OS argument (timespec / WaitOnAddress compare
    buffer).  A thread waiting for =nl_alloc_lock= re-entered the
    allocator and recursed until STATUS_STACK_OVERFLOW (located with cdb
    and the new opt-in link map, =NELISP_LINK_MAP=).  Wait scratch is now
    per-thread memory (env+1928 / bss).
  - Collections run on the main thread, whose 1 GiB stack the recursive
    marker needs.  A worker that finds one due sets =nl_gc_wanted=;
    =garbage-collect= in a worker asks and waits, parkable, up to 2 s.
    The main thread parks for, and collects at, its loop back-edges;
    =nl-bt-join-thread= waits in 20 ms slices so that it gets back-edges.
    The main thread's frame ring is always marked.  A missed park clears
    the allocation debt, so it backs off instead of retrying every
    iteration.
  - Chunk exhaustion takes =nl_alloc_lock=: retry the bump, then reuse
    from the free list, then grow.  The section no longer needs its
    8 MiB headroom precondition, and END returns 1.  Eager free-list
    pushes are switched off while a section is open.
  =tools/nelisp-bt-gc-smoke.el= (8 threads x 600 iterations, a worker
  =garbage-collect= every 200): every live sample is intact, with 108
  parked collections on windows (340 s); it passes on linux as well.
  Every earlier smoke passes on both targets.
- S7 (2026-10-18): =nl-bt-interrupt-thread=, =nl-bt-destroy-thread= and
  =nl-bt-thread-destroyed-p=.  Each thread has an interrupt word (main:
  bss; worker: env+1920), and the =while= back-edge checks it first.
  When it is set, the thread evaluates =(nl-bt--run-interrupts)= in
  place, and the hook's status now flows back into the loop, so an
  interrupt function that signals or throws ends the loop with that
  error.  Destroy queues a function that throws to the =catch= around
  every thread body, so =unwind-protect= cleanups run; joining a
  destroyed thread returns nil.  A thread blocked in a native wait (lock,
  condition, semaphore) runs its interrupts once the wait returns, and
  the main thread runs them while joining (20 ms slices).  On the emacs
  backend interrupts run at the target's next nl-bt yield.
  =tools/nelisp-bt-lifecycle-smoke.el=: BT-LIFE-PASS and
  BT-INTERRUPT-PASS 3/3 on windows and on linux (an interrupted busy
  worker carries on afterwards; a worker interrupts the joining main
  thread; destroy runs the cleanup).  Host ERT: 18/18.
