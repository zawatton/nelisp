* §0 Summary

GNU native-compiled code implements =condition-case= and =catch= with
=push_handler(tag,type)= followed by an /inline/ =_setjmp= on the returned
=struct handler='s =jmp= field, called through the artifact's own PLT. On a
=signal= or =throw= GNU runs =unwind_to_catch=, which unwinds the specpdl,
sets =handlerlist=, and =longjmp='s back into the native frame's landing pad.
Doc 207 makes NeLisp deliberately never enter that landing pad: the exit is
recorded, later callbacks are suppressed, the native frame runs to its return
and the exit is resumed. For a handler that /catches/ the error this is not
observably equal to GNU, because the handler body is code the native frame
must execute and then /continue/ normally.

Of the fixed 19 vendor functions exactly one uses handlers:
=byte-compile-form= (2 =push_handler= sites, both =CONDITION_CASE=, ledger
S6.10). This document specifies how to admit such frames:

1. GNU-exact =struct handler= / =struct thread_state= shadow blocks, owned by
   the NeLisp runtime, native-visible, never scanned by the GC (§2, §7).
2. A callable =push_handler= import port that mints a shadow handler block.
3. A =_setjmp= PLT target under NeLisp control and a =longjmp= issued only
   by the callback adapter /after/ all Lisp-side state of the callback has
   been released, and only to a handler in the /same native frame/ that made
   the callback (the /frame-local/ restriction, §4.A). No NeLisp interpreter
   or VM frame is ever skipped by a jump.
4. Handler matching, specpdl unwinding, =handlerlist= restoration and
   exactly-once landing performed on the Lisp side before the jump (§4.A.4).

Recommendation (§6): option A in its frame-local, template-verified form,
delivered in three ledger stages (S8-S10), the last of which closes S6.10.
Rust LOC added: zero (Lisp, the existing NeLisp x86-64 assembler, and the
AOT elisp DSL).

* Decisions (user, 2026-09-29)

- Q1/Q2: proceed with option *A1* (NeLisp's own assembler setjmp/longjmp
  pair bound to the artifact's GOT slot, runtime rip/rsp validation at the
  divert). A2 stays only as the documented fallback if the =.got.plt= slot
  proves unwritable after load (S8 verifies this first).
- Q3/Q4: frame-local landing is the admitted contract; =condition-case VAR=
  and =CATCHER= are deferred to a later stage (S11), outside the S6.10 path.
- Q8: *GNU order is required.* Before a native =CONDITION_CASE= handler
  catches, =handler-bind= handlers and the debugger decision
  (=debug-on-error=, =debug-ignored-errors=, =debugger=) run exactly as GNU's
  =signal_or_quit= runs them. This is a criterion (S9.6), not a known gap.
- Q5/Q7/Q9: only the =NELISP_READER_DYNAMIC= flavor loads .eln;
  handler-bearing native calls are main-thread only (already serialized);
  the rebuild and S6 evidence regeneration cost is accepted.
- Q6 (X support / struct size) is verified during S8.
- Ledger: S10.4 of the draft is dropped (it would re-count the existing
  S6.22 check); S10.3 is the stage-ending e2e and runs both the S6.10
  measurement and the S6.22 validator. Net new criteria: 13 (57 -> 70).

** S10 result (2026-09-29): what admitting =byte-compile-form= showed

- The source form behind the two =condition-case= regions is GNU's inlined
  =macroexp--const-symbol-p= (=macroexp.el:792=, a =defsubst=): =(condition-case nil
  (progn (set symbol (symbol-value symbol)) nil) (setting-constant t))=, guarded by
  =(if any-value ...)=. In the genuine body =any-value= is read from a stack
  slot whose only reaching definition (a reaching-definition analysis of the whole
  body, =0x13eb=) is the constant nil (=d_reloc= slot 2), so /both regions are
  unreachable at run time for every input/: the body never calls =push_handler=
  on the ordinary corpus, and the =forced= test mode makes them run by setting
  that live constant non-nil (no code byte touched). The handler mechanism
  itself (push, private =_setjmp=, guarded =Fsymbol_value=/=Fset=,
  =setting-constant= caught by the native handler, landing, pops) is then
  verified on the genuine body (5 pushes, 4 landings, identical transcripts).
- The frame-local rule is a separate checker over the actual bytes
  (=lisp/nelisp-eln-handler-frame.el=), not only a consequence of the exact
  template; the template's =:PLT-CALLS= displacements and the new GOT kind
  =current-thread= are checked against the =.plt= entry and the artifact's own
  =current_thread_reloc= root object.
- Registration binds the S8 substrate in =--load-1= for a body whose shape
  declares =:HANDLERS=; the body digest is declared in production
  (=nelisp-eln-registration--setjmp-declared-body-sha256s=).

** Remaining gaps after S9 (2026-09-29)

- The debugger decision runs in GNU order (before the native handler
  catches and before the native specpdl unwinds), but only after the Lisp
  frames between the raise and the native call have unwound, so a
  debugger's backtrace is shorter than GNU's.
- =signal-hook-function= is not run for errors that reach a native
  handler (GNU's =signal_or_quit= runs it first).

** §2.2 =struct thread_state= (=thread.h=)

=m_handlerlist= is at *0x68*: header 0x00, then nine Lisp_Object fields
(=last_thing_searched= .. =event_object=) at 0x08..0x48, =m_stack_bottom=

** §2.3 =push_handler= (=eval.c:1830-1867=)

=push_handler_nosignal=: takes =handlerlist->nextfree= or =malloc=s a handler,
then sets =type, tag_or_ch, val=Qnil, next=handlerlist,
f_lisp_eval_depth=lisp_eval_depth, pdlcount=SPECPDL_INDEX (),
act_rec=get_act_rec (current_thread), poll_suppress_count,
interrupt_input_blocked= (and =x_error_handler_depth=), then
=handlerlist = c=. It returns =c=; =push_handler= calls =memory_full= on
failure. It is a callback in the artifact's link table (freloc index 2,
=freloc-ba35c031.tsv=), currently a fail-closed stub
(=lisp/nelisp-eln-runtime-services.el:305-328=, registry row at =:721=).

** §2.4 The native call-site pattern and the landing pad

=emit_limple_push_handler= (=comp.c:2195-2220=): =c = push_handler(tag,type);
if (_setjmp(&c->jmp)) goto handler_bb; else goto guarded_bb;=. Genuine
bytes, region 1 (region 2 at =0x25e5..0x2c07= is the same with a different
frame base):

#+begin_example
24b1  mov  0x1e8(%rbx),%rdi        ; tag  = d_reloc[61] (a condition list)
24b8  mov  $1,%esi                  ; type = CONDITION_CASE
24c2  call *0x10(%rbp)              ; push_handler (freloc 2)
24c5  lea  0x40(%rax),%rdi          ; &c->jmp
24c9  call _setjmp@plt              ; PLT 0x1030 -> GOT 0x5000
24ce  test %eax,%eax
24d0  je   2b50                     ; 0: guarded_bb
24d6..24eb  landing pad: thread = **GOT[0x4fb0]; thread->handlerlist
            = thread->handlerlist->next          ; pop (no read of ->val)
24ef..250b  rax = d_reloc[0x198/8]; test; jump to the join
2b50  guarded_bb: Fsymbol_value(x) ; Fset(x, result)   ; same symbol twice
2b80..2ba1  normal-path pop_handler, same 3-load sequence, then join
#+end_example

Guarded region facts (region 1, =0x2b50..0x2ba9=): exactly two authenticated
port calls (=Fsymbol_value= freloc 1335 at =0x2b67=, =Fset= freloc 1334 at
=0x2b7a=), no local =call rel32=, no indirect call except through the
link-table register, no loop. The identity of the source form is
*UNVERIFIED* (=bytecomp.el= =byte-compile-form= at line 3403 contains no
=condition-case= textually; the handler comes from an inlined macro).

Landing-pad contract (from =comp.c:2333-2355= =fetch_handler= and the bytes
above): on arrival the code expects (a) callee-saved registers and =rsp= as
they were at the =_setjmp= call (GCC treats them as restored by setjmp),
(b) =eax != 0=, (c) =thread->handlerlist == c= so its inline pop yields
=c->next=, (d) stack frame slots written before the =_setjmp= intact,
(e) nothing about =c->val= for these two sites; a =condition-case VAR= site
would additionally load =c->val= (=+0x18=) via =fetch_handler=. Expectation
(c) is why the shadow =next= chain must be real, native-readable memory.

** §2.5 Search and unwind (=eval.c=)

- =signal_or_quit= walks =handlerlist= innermost first; for =CONDITION_CASE=
  it applies =find_handler_clause (tag_or_ch, conditions)= (=eval.c:2241-2261=):
  a match is =memq= of a condition in the error's =error-conditions=, or the
  element =t=. On a match it calls =unwind_to_catch (h, NONLOCAL_EXIT_SIGNAL,
  error)= (=eval.c:2064=) with =error = (SYMBOL . DATA)=. Debugger and
  =handler-bind= (type 4) participate in the walk; neither exists in admitted
  frames.
- =Fthrow= matches =CATCHER= by =EQ (tag_or_ch, tag)= (=eval.c:1477=) and passes
  the thrown value.
- =unwind_to_catch= (=eval.c:1423-1462=): store =nonlocal_exit= (+0x10) and
  =val= (+0x18) in the target; restore =poll_suppress_count= and
  =interrupt_input_blocked=; then loop { =unbind_to (handlerlist->pdlcount)=;
  advance =handlerlist= } until =handlerlist == catch=; restore
  =lisp_eval_depth= and =act_rec=; =sys_longjmp (catch->jmp, 1)=. So specpdl
  entries (including =unwind-protect= cleanups, which run Lisp) are unwound
  /handler by handler, innermost first, before the jump/, and the jump lands
  with =handlerlist == catch=.
- Non-local-exit state that is /not/ specpdl-managed and matters to NeLisp:
  none identified beyond the above; =poll_suppress_count=,
  =interrupt_input_blocked=, =act_rec=, =lisp_eval_depth= have no NeLisp
  counterpart for native activations (=*UNVERIFIED*= for =lisp_eval_depth=:
  NeLisp's own nesting counter is unwound by ordinary returns).

* §4 Design options

** §4.0 Invariants every option must keep

- I1 /Exactly-once/: a shadow handler record is consumed by at most one
  landing; its buffer is invalidated when consumed or retired.
- I2 /GNU order/: cleanups (native specpdl entries, then VM frames as they
  return) run innermost first, each before any outer one, all before the
  landing pad runs.
- I3 /No skipped NeLisp frame/: no NeLisp interpreter, VM, gateway or
  adapter state is discarded by a jump; only GNU-generated frames are.
- I4 /Doc 207 unchanged for everything unmatched/: an exit that matches no
  native handler of its activation takes exactly the current suppress-and-
  resume path.
- I5 /Fail closed/: any inconsistency (chain not a runtime-minted suffix,
  wrong thread, buffer or pointer out of range, unpopped handler at return)
  retires the activation with an error rather than continuing.

** §4.A Option A: NeLisp-provided setjmp/longjmp, runtime-owned shadow structs

*** §4.A.1 Shadow structures (runtime-owned, native-visible)

- One =thread= block (>= 0x80 bytes, zeroed) with =handlerlist= at 0x68
  pointing at the innermost /shadow handler/ of the running activation, or a
  runtime-owned sentinel handler (=next= = 0) when none.
- One 8-byte =current_thread= cell holding the thread block's address.
  Registration writes the artifact's =current_thread_reloc= cell (=.data=
  0x5800 of the genuine artifact) with the address of that cell, exactly as
  GNU's loader does; the loader verifies the cell was zero first.
- Handler blocks (0x140 bytes, zeroed, 16-aligned) minted by the
  =push_handler= port. The runtime writes =type=, =next=, and leaves
  =tag_or_ch=/=val= at 0 (native code never reads them at these sites; §2.4).
  The real Lisp tag (the condition list or catch tag) lives only in the
  Lisp-side record. Requests to the GC owner: §7.

*** §4.A.2 =push_handler= port

An admitted body imports freloc 2 through a port (=convention fixed=,
=arity 2=, =return raw=). The Lisp implementation, run inside the callback:

1. validates the activation (=frame=) is the top frame and its thread is the
   adapter's active thread (I5);
2. decodes =tag= (a GNU word from the body's declared constants, resolved
   through the existing constant-cell mechanism, not decoded from memory) and
   =type= (must be 0 or 1, else fail closed);
3. mints a block, links =next= to the current =thread+0x68=, records
   =(block type tag pdlcount)= on the frame's =:native-handlers= (a Lisp list
   held by the rooted frame), with =pdlcount = (specpdl-depth)=;
4. writes =thread+0x68 := block= and returns the block address as the raw
   word.

*** §4.A.3 =_setjmp= and =longjmp=

Two variants (choose in §6):

- *A1, private assembler pair.* Reuse =nelisp-native-jump-x86_64-emit-setjmp=
  and =-emit-longjmp= (=nelisp-native-jump-x86_64.el:31, :47=) in an
  executable page (=nelisp-native-load--mmap=). After the real =dlopen=
  (RTLD_NOW, so ld.so has already bound the slot to glibc), the loader
  overwrites =.got.plt= word at =bias+0x5000= with the stub address and reads
  it back. The private buffer needs 64 bytes and fits in the 200-byte =jmp=
  field. The stub is reachable only through that one GOT slot; its address is
  never given to Lisp as a callable.
  Requires: slot writable after load (=.got.plt= starts at =0x4fe8=,
  =GNU_RELRO= is =0x4dd0+=; the S6.7 code already reads the live slot, but
  writability is *UNVERIFIED*; fallback is A2).
- *A2, glibc-bound.* Leave ld.so's binding to libc =_setjmp=. Admission
  compares the live slot with =nl-ffi--dlsym= of libc =_setjmp= and requires
  =DT_NEEDED= exactly =libc.so.6=. The runtime lands with libc =_longjmp=,
  resolved once with =nl-ffi--dlsym= and invoked with =ptr-call= (as
  =nelisp-eln-system-loader.el:256= calls =dladdr=). No assembler, no GOT
  patch, but the runtime cannot validate the saved =rip=/=rsp= (glibc mangles
  them with the pointer guard) and depends on libc semantics
  (=_longjmp_unwind= runs pthread cleanup handlers: none exist in these
  frames, *UNVERIFIED* on the process's own stack).
  There is no CET shadow stack in the artifact (=readelf -n=: only a build-id
  note), so a non-glibc longjmp is safe for A1 (*UNVERIFIED* for the host
  binary).

*** §4.A.4 The divert: how a signal reaches the landing pad

The jump is issued from the adapter, not from Lisp, in this order
(the adapter today does capture, =nl_root_release=, =finish=, return; the new
step is added after =finish=):

1. Dispatcher (Lisp) traps an =error=/=quit= (as today, =callable-import.el:423=).
   Before recording it as the frame's =:condition=, it reads =thread+0x68=,
   checks the chain against the frame's =:native-handlers= (I5), prunes
   handlers the native code already popped (its pop writes only =+0x68=),
   and walks innermost first applying =find_handler_clause= semantics
   (=memq= over =error-conditions=, or =t=) for type 1.
2. On a match H: run =unbind_to= for every handler from the innermost to H,
   each to its recorded =pdlcount= (=--unbind-1= repeated;
   =callable-import= already exposes =helper-unbind-n= to the bridge). Cleanups
   that raise a new exit replace the exit, as GNU (the new exit re-enters
   step 1 with the remaining chain).
3. Drop the records above H, release their blocks; write =H.nonlocal_exit=
   (+0x10, =1= signal) and =H.val= (+0x18: 0 for these sites; a
   =condition-case VAR= site needs the encoded =(SYMBOL . DATA)= through the
   existing activation-lease codec, so it stays inadmissible until the codec
   can encode it, §8 Q4); write =thread+0x68 := H=.
4. Clear the frame's suppress state (the exit is consumed, I4), store =H= in
   a runtime cell =nl_eln_native_resume= (address of H's =jmp= buffer, value 1),
   and return a normal answer pair.
5. The adapter (AOT DSL), after =nl_eln_callback7_finish=, reads and clears
   =nl_eln_native_resume=; if non-zero it releases the callback lock (already
   released by =finish=) and jumps: =longjmp(buffer, 1)= (A1: the stub; A2:
   =ptr-call _longjmp=). Otherwise it returns the word as today.

Why no NeLisp frame is skipped (I3): step 5 runs after the gateway, the
dispatcher, every VM frame under the raising callback, and every root/pin
mark of the adapter have returned or been released. The frames discarded
are the adapter's own leaf frame and GNU-generated frames between the
adapter and the target.

Frame-local restriction: the target must be in the /same/ native frame that
called the port that raised. Admission proves it: between the =push_handler=
return and each matching pop the body has only authenticated port calls
(=call *slot(%reg)=), forward control flow, no local =call rel32=, no PLT
call other than =_setjmp=. Then no unknown native frame exists between adapter
and target, and the target's =rsp= is exactly the adapter's caller frame
(checkable with the recorded =rsp= in A1). A body whose guarded region calls
another native function (nested native frames) is not admitted by this
document.

*** §4.A.5 Trust model C: what must be template-verified

Exact-byte template for the body and =top_level_run= remains the unit of
trust; on top, this document adds these mandatory checks to handler-bearing
templates:

- each =push_handler= call is preceded by the exact tag load (declared
  constant) and =mov $1,%esi=, and followed by exactly
  =lea 0x40(%rax),%rdi; call PLT(_setjmp); test %eax,%eax; je/jne=;
- the PLT/GOT surface is exactly PLT0 + one entry, one JUMP_SLOT at the
  fourth =.got.plt= word whose symbol is the undefined =.dynsym= function
  named =_setjmp= with version =GLIBC_2.2.5=, =DT_NEEDED= is exactly
  =libc.so.6=, =DT_JMPREL/PLTRELSZ/PLTREL= name only it (extension of
  =--plt-target-name=, =registration.el:1778=);
- the only thread/handler memory operations in the whole body are the
  3-load path, thread+0x68 read/write, handler+0x20 read and the address
  computation +0x40 (a linear byte-pattern scan of the body for any other
  displacement off those registers is part of the template, not inferred);
- =current_thread_reloc= GOT slot (=GOT 0x4fb0=) is the artifact's own
  =.data= object and initially zero;
- the guarded region contains only authenticated port calls (frame-local
  rule).

Attack surface of a callable setjmp: an artifact that could reach the stub
with a free =rdi= gets a 64-byte (A1) or 72-byte (A2, =__mask_was_saved=)
write at any address, and a forged buffer would redirect control. Both are
closed by exact templates (no free =rdi=) plus, for A1, the runtime check at
the divert that the buffer's =rip= lies in the authenticated body range and
=rsp= is the expected value (A2 cannot check). The stub's address is
installed in one GOT slot of one admitted artifact.

*** §4.A.6 Correctness argument versus GNU

For the admitted shape, GNU's observable sequence is: search -> unbind in
handler order -> =handlerlist= := target -> jump with =eax=1=. The design
produces the same sequence in the same order, the same landing register
state (setjmp-saved callee-saved registers, =rsp=, =rip=, restored by the
same pair that saved them), and the same post-landing native pop
(=handlerlist = H->next=, executed by the artifact's own bytes on shadow
memory that has a real =next=). Differences, all declared: the search does
not visit debugger or =handler-bind= entries; =lisp_eval_depth=,
=poll_suppress_count=, =interrupt_input_blocked=, =act_rec= are not
restored (no counterpart); an exit passes VM frames deeper than the native
frame before the handler match (Doc 207 §3.5 already covers this for
native-to-native).

*** §4.A.7 GC and roots

Native-visible blocks hold no Lisp pointers; tags and values live in the
frame plist (a rooted Lisp structure) and reach native code only as
authenticated constant words or activation leases. The GC is not asked to
scan or move any block (§7). The discarded native frames hold GNU words for
units the frame already leased; those leases stay until the activation
retires, so nothing dangles.

** §4.B Option B: trampolining (no native longjmp)

Split an admitted body at handler boundaries: the guarded region runs under
NeLisp's own =condition-case=; the handler region is a separate continuation
invoked by NeLisp; native code never longjmps.

Feasibility check against the real code: the guarded region (=0x2b50..0x2ba9=)
is not a function. It shares the stack frame (=0x38(%rsp)=, =0x48(%rsp)=
slots), callee-saved registers (=rbx= = constants base, =rbp=/=r12= reloaded
from =(%rsp)=) and the join point =0x2502= with the enclosing body. Splitting it
needs one of:

- *B1 code rewriting* (patch the body so the region becomes a callable and
  the landing a resume point): breaks "exact genuine bytes", the premise of
  trust model C. Rejected.
- *B2 region emulation*: a template-verified straight-line subset interpreter
  in Lisp executes the region and the landing pad (about 20 instructions per
  region here: =mov/lea/test/jcc/call *slot/movups/punpcklqdq/jmp=), then
  hands control back to native code at the join with a synthetic register and
  stack state. This needs an x86 decoder proven equal to hardware, register
  and frame reconstruction, and a way to re-enter native code mid-function,
  which /is/ a longjmp-like transfer (to the join address with rebuilt
  registers) but built from scratch. It shrinks to A's problem plus a
  decoder.

Trade-offs: correctness argument is stronger for control flow (no native
frame discarded at all) but weaker for state (emulated instructions must
match the CPU); trust model C impact: the interpreter's subset is a new
trusted decoder, and every template needs the region proven inside the
subset; attack surface: none from setjmp, but the decoder is a new parser of
adversarial-looking bytes; GC: none; Rust LOC 0; size 1500-2500 lines
(*UNVERIFIED*); generality: each new handler shape needs the emulator to
grow. Test plan: differential decoder tests against hardware execution for
each instruction form, plus the shared handler probes.

** §4.C Option C: keep S6.10 out of scope

Leave =byte-compile-form= on the VM (host/VM results already equal, S6.10
notes 2026-09-28). No new trusted code. Consequences: ledger S6.10 stays a
=pending= row and S6.22 stays a known-red =cmd= (it requires all 19); to make
the ledger truthful without a mechanism the user must edit the criteria
(the meter forbids downgrading a red check), which changes the denominator.
Rust LOC 0, size 0, GC none, attack surface unchanged. Correctness: not
applicable (function not native). Test plan: none new; keep the existing
negative that the artifact is rejected with
=top-level-instructions-not-admitted=.
