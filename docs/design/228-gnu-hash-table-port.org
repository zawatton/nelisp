#+TITLE: GNU 31.1 hash-table storage port
#+STATUS: IN-PROGRESS

* Source and representation
GNU Emacs 31.1 is the oracle. This port changes hash storage only. The
word-heap runtime still exposes the existing table handle (a cons whose
car is metadata); keys and values occupy words in a native vector rather
than individually allocated entry conses. This handle is an architectural
adaptation, not a per-entry allocation.

* Metadata contract
Slots 0-10 retain the existing marker, count, test, capacity, weakness,
legacy budget, identity generation/address, custom descriptor, callback
guard and transient weak-chain link. Slot 11 is key_and_value, 12 is
hash, 13 is next_free, 14 is next. The handle cdr is index. Empty keys
use the immediate -1 sentinel in hash (all occupied hashes are unsigned
32-bit), so every Lisp object, including nil, is a valid key. Slots in
next and index store -1 for end of chain. Native reserve publishes all
new vectors together after allocation, preserving old indices and order.

* Boundary and checks
No public primitive is added for this representation. Existing hash
allocation/tagged-object access uses minimal-native clause 1. Lisp owns
keyword validation and user-defined callbacks; the native storage does
not evaluate arbitrary callbacks outside the existing evaluator bridge.
The Lisp reserve, custom insertion and removal functions in the prelude
retain a reference implementation using the same vectors. Custom tests
perform growth in that reference: the existing user-test callback ABI
returns the final result and exposes no native reserve operation. Extending
that evaluator ABI or adding a new native entry is outside this storage
port; ordinary eq/eql/equal tables grow entirely in native code. Layout acceptance checks actual populated storage and free
chains, with the old cons representation as a negative control.

Weak storage adapters call existing GC entry points through their native
ABI, rather than duplicating the general tracer inside the adapter. GC
roots and the native compiler are unchanged.

Weak endpoint marking depends on the collector/root lane. The sweep is
adapted to the new vectors; unresolved GNU weak fixture differences stay
red in S1.2 and are recorded with their exact case names.
