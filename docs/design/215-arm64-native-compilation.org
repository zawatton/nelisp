#+TITLE: Doc 215 — AArch64 native compilation on Linux and macOS
#+STATUS: DRAFT — design only; A1–A5 execution qualification pending
#+DATE: 2026-10-11
* Scope, evidence and decisions
The required backend is in-house raw-v2, first synchronous explicit opt-in,
then templates and full corpus qualification. Reuse GNU bytecode, the shared
rooted CFG, semantic validation, frame/exit protocol and authenticated cache.
Use one little-endian AArch64 emitter/relocator and separate Linux/Darwin OS
adapters. Windows arm64, legacy boxed trampolines, GNU ELN and development
allocator/GC replacement are outside M1; none may become accidentally enabled.

Labels throughout: [V] verified from fec44b49f983c815ff1f9640548b184662938903
source or the identified host probe; [R] verified published reference, linked
below; [P] proposed replacement, unimplemented/unqualified; [A] assumption
requiring the stated execution receipt. No statement here claims arm64 native
trust admission, F1 execution or performance already passes.

per-thread W^X, not a dual mapping. The native loader uses documented libSystem
APIs through reader-owned Mach-O imports, not new Darwin syscall numbers.
Linux uses RW -> RX mmap/mprotect and explicit instruction-cache publication.
Do not broaden a host predicate until proof, mapping and identity owners exist.

* Shared AArch64 implementation contract [P], ABI facts [R]
- x0–x7 integer arguments, x0 integer return; v0–v7 FP arguments, v0 scalar return.
  Save used x19–x29 and low halves of v8–v15; save LR x30 across calls,
  maintain 16-byte SP alignment, no red-zone dependence and no x18 anywhere.
  Fixed u64 internal signatures are shared. Darwin small C arguments require
  caller extension and Darwin variadic arguments need a separate stack ABI.
  Existing nelisp-aot-compiler--emit-defun saves x30/x29 in separate 16-byte slots [V]; Darwin
  needs a valid contiguous [previous FP,LR] frame record at x29. Adjust spills
  and incoming stack offsets together; host decode plus real stack walk verify.
  Lisp exits remain status/root records; foreign unwinding through JIT frames
  stays refused until DWARF unwind registration and teardown are qualified.
- Fixnum add/sub/neg use ADDS/SUBS followed immediately by B.VS to the exact
  fallback; then enforce signed 62-bit bounds before storing tag/payload.
  MUL does not set V: keep 30-bit guards initially; wider multiplication needs
  SMULH/sign-extension validation. Preserve input aliasing and slow exits.
- B.cond/CBZ have signed imm19*4 ([-1 MiB,1 MiB-4]); B/BL imm26*4
  ([-128 MiB,128 MiB-4]). Reuse inverted-condition + B; distant B/BL use
  local veneer islands, LDR literal x16 + BR x16 (BL to veneer preserves LR).
  Layout reserves bounded islands/pools before final fixups; reject overflow
  rather than truncate. ADR/LDR literal have ±1 MiB reach; align address
  literals to 8, branch around pools and exclude them from code decode/spans.
- ADRP uses Page4K(S+A)-Page4K(P), ±4 GiB, plus low 12-bit ADD; for slot loads
  use scaled LDR and prove access alignment. ELF types are
  R_AARCH64_CALL26/R_AARCH64_JUMP26, R_AARCH64_ADR_PREL_PG_HI21, R_AARCH64_ADD_ABS_LO12_NC,
  R_AARCH64_LDST64_ABS_LO12_NC, R_AARCH64_ABS64; Mach-O uses ARM64_RELOC_BRANCH26, ARM64_RELOC_PAGE21, ARM64_RELOC_PAGEOFF12, ARM64_RELOC_UNSIGNED
  with its own addend records. Current helpers lack JUMP26/scaled-lo12/pool
  support [V]; extend deliberately. Initial raw imports need CALL26 to local
  absolute stubs only; static reader BSS keeps existing ADRP+ADD relocations.
- Poll sequence: publish roots -> authenticate ticket/slots -> LDR state;
  compare epoch/env/depth, recompute dynamic flags if stale -> LDR allocator
  growth/debt -> compare -> local condition/B to slow gate only when due ->
  reauthenticate and publish status/exit before root release. No cached GC debt
  or unrooted Sexp across a callback. Retain the nine-slot source contract.
  Atomic arm emit currently uses LDADDAL/CASAL unconditionally [V]; detect
  FEAT_LSE and provide conservative LDAXR/STLXR + barriers fallback for
  baseline Linux ARMv8 hosts. Sealed feature choice belongs in compiler proof.
* Linux aarch64 OS adapter [P]
Use EM_AARCH64 ELF reader, raw .nelr JIT text, mmap=222/mprotect=226/munmap=215
with Linux flags; translate other x86 vocabulary via Doc 151 where appropriate.
Bounded reads need openat=56/pread64=67/close=57; direct syscall calls are native
numbers, not automatically translated. Use AT_PAGESZ from startup auxv for
4K/16K/64K mapping/budget; ELF PT_LOAD congruence/alignment must also support
the selected kernel granule. Synthetic rounding tests do not prove real 64K.
Cache maintenance equivalent to __clear_cache: read CTR_EL0 line sizes, align
D/I starts independently, DC CVAU each D line -> DSB ISH -> IC IVAU each I
line -> DSB ISH -> ISB, respecting IDC/DIC. Provide a reader-owned callable
helper; no runtime compiler/C toolchain dependency. Publish entry only after
flush/protection completion; cross-thread execution needs ordered publication
and receiving-thread instruction synchronization. qemu cannot prove real cache
coherence; require hardware repeated code replacement/unload/remap checks.
* Darwin arm64 OS adapter and bootstrap [P]
[V] Existing nelisp-standalone--macos-alloc-chunk-form uses Darwin mmap 197/munmap 73 and
nelisp-standalone--os-syscall-xlat-forms translates file/stat/dir calls. AOT
nelisp-aot-compiler--emit-syscall-direct-arm64 puts NR in x16, uses SVC #0x80 and CSNEG on carry
to turn positive Darwin errno into negative status. It supports ordinary
reader storage, not pthread JIT APIs. [A] These private syscall conventions
remain usable on the user's OS; old comments record measurements, not this
session's execution. Darwin numbers are not a stable application ABI.

[V] nelisp-mach-o--build-executable already names dyld/libSystem, but
nelisp-mach-o--exe-chained-fixups has zero imports; nelisp-link-units-macho-exec resolves
only internal symbols. Thus nl-ffi-call is presently unsupported on Darwin.
[P] Add bounded Mach-O bind/import cells and arm stubs, route a reviewed
libSystem subset through existing nl-ffi-call; no host Emacs subprocess can
substitute for calls in the reader. Require mmap/munmap/mprotect, getpagesize,
pthread_jit_write_protect_np, sys_icache_invalidate, __error, executable path
and bounded file/cache APIs. Use named imports and correct C return widths;
libc errors use -1/MAP_FAILED plus __error(), not the SVC carry convention.
Bootstrap imports must work before native trust/cold restore. Do not hand-map
dyld shared-cache pointers or synthesize private pthread/Mach syscalls.

[P] Reserve one MAP_JIT arena at startup, as hardened-runtime JIT supports one
region [R]. Suballocate bounded page-rounded immutable code+stub slices.
Validate/cache-authenticate and prepare ordinary RW bytes first; a non-JIT
reader helper locks the arena, disables write protection on that thread,
copies/relocates without callbacks/JIT entry, restores protection on every
exit and calls sys_icache_invalidate before entry publication. Other threads
retain their own protection state; serialize writes and prevent execution of
unpublished/recycled slices. Individual unload retires slices only after last
call/owner, not munmap of the arena; failed loads release unpublished slices.
R GC tables and scratch mappings use ordinary libSystem memory APIs.
This MAP_JIT per-thread policy replaces Linux's RW->RX transaction; do not
claim the mapping's static VM flags alone prove W^X.

[P] Query getpagesize and assert current arm macOS 16K expectation [A]. Sign
the final stamped reader with codesign -f -s - --options runtime --entitlements
the reviewed plist containing com.apple.security.cs.allow-jit. Verify signature
and entitlements before running, and test missing-entitlement refusal separately.
Do not add jit-write-allowlist with the selected pthread_jit_write_protect_np
strategy: that entitlement disables this API [R]. Do not require unsigned-code
or library-validation exemptions for the in-house/system-library lane.
Ad-hoc signing is local/CI qualification; Developer ID/notarization distribution
is a separate release task. Existing raw syscall bootstrap remains a release
risk even after this loader uses libSystem; qualify file/startup/cold paths on
each supported macOS release and migrate them separately if a receipt fails.
Any new native helper/builtin must meet AGENTS.md clause 3 (OS/cache access),
with reference form, inventory and census/S1.4/55s NOTE measurements; prefer
the existing FFI entry. No native arithmetic builtin is justified for speed.
