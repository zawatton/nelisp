#+TITLE: Doc 215 — Word transport: retire the 32-byte transport box
#+STATUS: IN PROGRESS
#+LEDGER: tools/ai/box-review-progress.org

* Reading of the goal

Transport only.  Every runtime function passes and returns 64-bit tagged
WORDs: fixnum =(n<<2)|1=, nil =3=, t =7=, otherwise a pointer to the
object's 32-byte Sexp box.  The 32-byte boxes that exist only to carry a
value between functions (a materialised view of an immediate, a scratch
copy, an out-parameter slot) go away.

The heap object layout does NOT change: cons, string, vector and record
objects keep their 32-byte Sexp header box and their existing payload
layout, and containers keep storing WORDs (Doc 147).  A pointer WORD is
still the address of an object's 32-byte box; what disappears is the
box that is allocated per read or per call to carry a value.

Out of scope until eval/bytecode-20261018 merges: =wf_bytecode_*=, which
that lane rebuilds on words.  =m5_fx_*= and =nl_fx_*= belong to the
eval-s2s3 lane; edits there are coordinated first.

* Rooting rule

Facts, read from the source at e0ab2ae3a:

1. Nothing moves in production.  =268435608= (compaction) is written 0 at
   boot (Doc 152 §11.21).  =nl_gc_collect= compacts only when that flag is
   1 *and* the conservative scan pinned nothing.  The mid-form collector
   (=nl_gc_midform_collect= -> =nl_gc_collect_from_recorded_roots 0=), the
   parked collector used under live workers, and the explicit
   =garbage-collect= builtin are always mark+sweep.  So =nl_gc_compact=
   cannot run mid-form, and a pointer WORD's value stays valid for the
   object's lifetime.
2. The conservative scan pins.  =nl_gc_conserv_maybe= walks the main
   thread's native stack from the current =rsp= to the driver-entry top
   (=268436456=), resolves each word to its owning block, marks it 4
   (pinned) and scans that block's payload as opaque words, transitively.
   A pinned block is never freed by the sweep and blocks compaction.
3. The scan is on in every production mode: the driver writes =268436464 = 1=
   at boot.  Only the debug primitive op 28 turns it off (op 29 back on);
   that configuration is for proving whether a precise root arm is
   load-bearing, and it is where =m5_fx_run='s float local was lost.
4. Worker threads (Doc 199) have no native-stack scan.  Their roots are the
   recorded EvalCtx and the private reserve at =env+4096=
   (=nl_gc_mark_thread_roots=).  A collection runs only with every worker
   parked at a safepoint.
5. Root-stack slots reserved inside a binder overwrote a parallel =let='s
   pending values, which sit just above the root-stack top while it binds
   them one by one.

Rule:

- R1 (main thread).  A pointer WORD held in a native local or argument
  stays alive and valid across an allocating call or safepoint: the scan
  pins its block and nothing moves.  No root slot is needed for it.
- R2 (worker-reachable code).  A WORD that must survive a safepoint in code
  a Doc 199 worker can run must also be reachable from a precise root: the
  worker's private reserve (=nl_root_reserve=) or a rooted container.
  Converting a box to a WORD never weakens this: a fresh transport box in a
  native local was itself unrooted, and the WORD references the same
  object the box did.  A box that WAS in a root slot keeps a root slot.
- R3.  Never reserve root-stack slots inside a binder or anywhere a caller
  may hold pending values above the root-stack top (fact 5).  Reserve in
  the caller before binding starts, or keep the WORD where R1 covers it.
- R4.  A WORD read from a container is the container's own child pointer:
  it cannot be clobbered by a later lookup the way a shared scratch view
  can.  An argument that is still a scratch view (from unconverted code)
  must be converted to a WORD at the call boundary, before any lookup.
- R6. A root slot containing a copied Sexp header traces its payload and
  child WORDs, not the original header allocation. After a safepoint, read
  the root view or a canonical WORD stored inside its rooted container.
  Do not keep using the original holder header merely because a copy of
  that header is rooted. The parked-worker prog1/prog2 check fails with
  =parked prog1 value lost= on =b93edbd90='s static build and passes after
  switching the reads to the root slots. It verifies two registered workers,
  an actual parked mark/sweep, and unchanged missed-collect diagnostics.
- R5.  If compaction is ever re-enabled, R1 still holds for the main
  thread because any conservative pin vetoes compaction; R2 code would need
  forwarding, which is why the parked collector never compacts.

** Evaluator argument transport (Round 2)

=nl_eval_arg_list_w= evaluates left-to-right in a host loop and answers the
argument-list WORD.  The evaluator calls this producer directly; the old
=nl_eval_arg_list= and =nl_eval_arg_list_walk= entries adapt only legacy
callers.  Four checked roots retain the current input cons, evaluated value,
head payload and tail payload, replacing seven roots and their status/view
traffic.  Root views borrow payloads; they do not retain the original heap
header.  The first cons is built in its root, later links use durable cons
WORDs, and the final result header is allocated while the head is still
rooted.  No safepoint occurs between releasing the roots and the caller
publishing the returned value in its own root.  Dotted-tail truncation and
error propagation are retained.

Macro application consumes =nl_apply_function_w= directly.  The expansion
cache still requires a pointer view, so only an immediate expansion is
materialised there.  Cell evaluation returns its value WORD directly while
retaining the N3 marker-13107 rule: a shared captured cell contains a pair
whose cdr is the value.  =test/abi-cell-word-test.py BINARY= covers eight
ordinary/shared immediate cases and fails on the naive direct-cell rewrite.

The N3 lambda mode path now preserves the result WORD through flag save and
restore, rather than making three nested WORD -> OUT -> WORD round trips.
The ordinary function lookup and recursive symbol-apply paths consume the
definition WORD directly; only an invalid immediate function definition
needs a view for the legacy type/error dispatcher.  Missing definitions
still signal =void-function= at the caller, rather than a generic ABI error.
Lambda/progn bodies read form WORDs and store cursor views without cloning.

Use =NELISP_BIN="$ABI_BIN" emacs --batch -Q -l
test/nelisp-lambda-body-loop-test.el -f ert-run-tests-batch-and-exit= to test a
selected build.  Previously this suite ignored NELISP_BIN and skipped two
runtime cases when =target/nelisp= was absent (1/3 executed, 0.000567 s).
It now executes all three (3/3, 6.440986 s); a failing selected binary makes
both runtime tests fail.  This fixes coverage without rebuilding or copying
the selected executable to =target/nelisp=.

* Coexistence ABI

- A converted function takes WORDs and returns the value WORD.  0 is never
  a valid WORD (a fixnum is odd, nil is 3, t is 7, a box pointer is
  non-null), so 0 means failure with the signal stashed (the existing
  =268435472= pending-signal stash), matching the =*_ptr= accessors' 0
  for a wrong-type container.
- Unconverted callers reach a converted callee through =nl_val_store_word=
  (32-byte slot -> WORD); a converted caller reaches an unconverted callee
  through =nl_val_load= / =nl_sci_store_imm= (WORD -> view).  Both shims
  are census debt and must reach 0 per family.
- Setters (=nl_record_set_slot=, =nl_vector_set_slot=,
  =nl_consbox_set_car/cdr=, =nelisp_cons_construct=) already accept a WORD
  for the value: they go through =nl_val_clone_into=, which stores an
  immediate WORD as it is.  A =*_ptr= read whose only consumer is a setter
  converts by passing the raw WORD.
- Families convert one at a time, cons accessors and their immediate
  callers first.  Each family's gate is its census row at 0 plus every
  behavioural gate in the ledger.

* Builtin word ABI (eval/abi-20261018)

** Contract

- A converted builtin or producer =F_w= takes WORD / view arguments and
  returns the result WORD.  0 means "failed, signal stashed" (THROW flag
  @268435472, TAG @268435480, VAL @268435512, as every rc=1 path already
  does).  2 means "not found / not handled / end of input" and is used
  only by the env lookups, =nl_apply_special_w= (the special-form
  dispatcher's old rc 2) and the reader's =nelisp_reader_*_w= (EOF), as
  listed below.  Neither 0 nor 2 is a WORD: a
  fixnum is odd, nil 3, t 7, a box pointer is >= 4096 and 8-aligned.
- Arity is kept even: a function that loses its OUT parameter takes a
  trailing =_pad= instead (callers pass 0).
- The returned WORD may be the object's own box (a cons cell's car is
  returned as the child box, not a copy).  A caller must never write into
  a WORD it received; it stores it through a setter or =nl_abi_word_to_rc=.

** Coexistence (one function at a time)

S6.2 also counts inline box/view decoding: a tag read paired with fixnum
payload encoding, or a private producer OUT box decoded via canonical
nil/t name predicates. Returning a freshly written heap box as the object
itself is not a conversion. Selecting nil/t before allocating a heap symbol
is a direct WORD producer, not decoding a producer's OUT box; the detector
checks the allocation scope. It is shared by the build census and
=box-census.py from-dump=; zero rows certify that it ran. Old
censuses without these rows cannot pass S6.2. This Round 3 criteria change
keeps the denominator at 21. The reader's pool-slot reverse adapters remain
debt until its producers and consumers carry WORDs directly.

The conversion-call counters use a complete expression walk as well. The
historical general census walk skipped the first binding initializer; this
hid =m5_fx_slot_word='s direct decode. Direct/reverse conversion calls now
visit every initializer, including extern calls, while binding names and
quoted data remain excluded. Non-conversion idioms retain their historical
baseline. Both build and from-dump use the same conversion walker and emit a
zero =conversion-walk-v2= certificate per unit; S6.2 rejects older records.
This criteria correction adds one dependency to the array checkpoint:
TOTAL 1486 -> 1487 and S6.2 66 -> 67. Earlier checkpoint numbers use the old
walk. The denominator and threshold remain 21 and zero respectively.

- Every converted =F= keeps its old name and (rc, OUT) ABI as a one-line
  adapter: =(defun F (.. out) (nl_abi_word_to_rc (F_w .. 0) out))=.
  =nl_abi_word_to_rc= stores an immediate with =nl_sci_store_imm= and a
  pointer WORD with a 32-byte copy (what the old =wf_copy32= arms did),
  returns 1 for 0.
- The reverse adapter =nl_abi_rc_to_word rc out= turns an unconverted rc
  form that wrote a private fresh box into a WORD: the box itself is the
  value (=nl_val_store_word=), so there is no extra copy.
- Dispatch tables: an arm is either legacy =(MATCH . RC-FORM)= (writes the
  free variable =out=) or word =(MATCH :word . WORD-FORM)=.
  =nelisp-standalone--applyfn-build-dispatch= with WORD-ABI wraps legacy
  arms as =(let ((out (alloc-bytes 32 8))) (nl_abi_rc_to_word RC-FORM out))=
  (=nelisp-standalone--applyfn-word-arm=); without WORD-ABI (other
  dispatch users) it wraps word arms as =(nl_abi_word_to_rc FORM out)=.
  =nelisp-standalone--guard-fixed-arities= keeps the marker and answers 0
  on an arity error.
- Generated dispatchers: =nelisp_apply_function_w (func args env _pad)=
  holds the dispatch; =nelisp_apply_function (func args env out)= is the
  adapter.  While an arm is still legacy it costs one private 32-byte box
  per call inside the WORD dispatcher (the callers' OUT box did the same
  job before); converting the arm removes it.

** The three blockers from the dry run

Round 3 reader conversion: the recursive parser carries WORDs directly,
including list/vector elements, dotted tails, quote wrappers, labels,
records, hash tables and byte-code literals. The sequence head/tail and
label value entries in the reader arena contain WORDs, while lexer scratch
and the cursor retain their distinct storage layouts. The old reader APIs
only adapt WORDs to their callers' OUT slots. The source-context (#$) view
is still an explicit box-to-word dependency and remains in S6.2.

=python3 test/abi-reader-word-test.py DUMP= rejects recursion through the
old producer APIs (27 findings before, zero after, 21 WORD entries checked).
Do not test WORD validity with numeric ranges: zero and negative fixnums
are valid WORDs. Test 0 (failure) and 2 (EOF) individually.

Socket/thread producers now return WORDs, including the clone dispatch and
join finish helpers; their old names retain the OUT adapters. Dispatch arms
are explicitly =:word=. A signal-only unsupported arm calls =nl_abi_fail=
without allocating an unused result box. Symbol constructors select nil/t
before allocating the heap symbol; unibyte string constructors return their
own freshly written heap header. No new reader builtin name is introduced.

=test/standalone-abi-io-word-check.el= exercises send/recv/poll/close through
Linux pipes, including embedded NUL/255 bytes, empty EOF, booleans and fd
errors. This covers the same read/write producers when network =socket()=
is denied by the sandbox (EPERM on both baseline and candidate). It does
not replace the real network round-trip smoke outside that sandbox.

The function special form reads its argument WORD directly. Unwind-protect
and condition-case retain a saved value as a cons child WORD in a checked
root. GC therefore traces the value's owning header and can update its
reference before cleanup/handler evaluation finishes. Final readers use
=nl_cons_car_word=, then release the mark without a later safepoint before
the caller publishes the result. This avoids copying a root view into a
private result box and decoding it. The error-trapping evaluator entry also
returns the evaluator's WORD directly; it retains the worker mirror-guard
recovery and preserves a non-signal abort without inventing an error.

=test/standalone-abi-saved-word-check.el= checks 36 cases: saved identities
through GC, :success, body/cleanup errors, throw payloads, nested reraising,
and immediate function literals. GNU Emacs and the baseline agree. A GC
failure injected into cleanup must fail rather than print its PASS marker.

Hash mutation is separated from its result: the shared mutator accepts the
setters' WORD/view inputs and returns raw status (1 is a missing table, not
an error). WORD entries receive the original value WORD and return it;
legacy OUT entries copy the original view. The legacy copy helper similarly
copies views, while its WORD entry is an identity operation on a WORD.
Neither result path decodes a private output. List slow paths use autoload
lookup/application WORD producers directly and explicitly handle 0/2 lookup
answers. Nthcdr carries WORDs, butlast has a WORD collector, and numeric
comparison produces nil/t WORDs before releasing its roots.

Validated string conversions and native-subr/process construction already
write heap objects; their fresh headers are returned directly. The consumer
check covers 55 cases, including nil/t/zero hash values, growth, immediate
list tails, numeric comparison, string lifetime through GC and table parents.

dynamic-binding exclusions, local declarations, reflection capture and the
explicit eval-alist shared-cell mode. The old output entries adapt the final

** Failure, "not handled", and the integration passes

- =nl_abi_fail RC _pad= is the one way to answer "failed": RC is the value
  of the call that stashed the signal and is ignored; it returns 0.  When
  the THROW flag (268435472) is clear it first stashes
  =(error "nelisp: word ABI failure without a stashed signal")=, so a bare
  0 can never surface later as a garbage error.  Write
  =(nl_abi_fail (bf_wrong_type_listp a) 0)=, never =(seq ... 0)=.
- 2 = not found / unhandled / EOF (lookups, special dispatch, reader).  The env
  lookups (=nelisp_env_lookup_value_w=, =nelisp_env_lkv_mirror(_with_frames)_w=,
  =nl_env_lookup_val_w=, =nelisp_env_lookup_function_w=) answer 2 where the
  legacy ABI returned rc 1 without a stash (unbound / no entry; for
  =nl_env_lookup_val_w= also an entry holding only the env+64 unbound
  marker), =nl_env_lookup_val_done_w= and =nelisp_mirror_lookup_value_w=
  (no entry; its adapter still writes nil); their adapters map 2 back to
  the legacy answer (=nl_abi_lookup_to_rc=: rc 1).  The reader (G3) uses 2
  for end of input the same way: a =nelisp_reader_*_w= answers the value
  WORD, 2 at EOF, or 0 after stashing =invalid-read-syntax= (a generic
  error when the legacy path left the signal to its caller), and every
  consumer tests =(= w 2)= before using W.  A miss never goes through =nl_abi_fail=:
  that would stash a generic error and leave the THROW flag set.
- Apart from those lookups and the reader, 2 ("not handled") is produced
  only by =nl_apply_special_w=.
  =nl_abi_word_to_rc= hands 2 through as rc 2, so the =nl_apply_special=
  adapter keeps its contract.  Every other consumer of =nl_apply_special_w=
  tests =(= w 2)= before using W; no =_w= function outside these three
  families may return 2.
- =F_w= keeps F's parameter list with the OUT parameter renamed to a
  =_pad= at the same position (callers pass 0).  The integration tools
  rely on this.
- =python3 tools/ai/box-apply.py flip-arms= (run once after the group
  merges) rewrites each literal arm =((MATCH) . (F .. out ..))= whose =F_w=
  exists into =((MATCH) :word . (F_w .. 0 ..))=.  Its only edits are the
  =:word= marker, the callee name and the one =out= argument (OUT is not
  bound in the word dispatcher).  Arms whose form is not a single such call
