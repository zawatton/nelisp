#+TITLE: Doc 215 — Word transport: retire the 32-byte transport box
#+STATUS: IN PROGRESS
#+LEDGER: tools/ai/box-review-progress.org

* Reading of the goal

Transport only.  Every runtime function passes and returns 64-bit tagged
WORDs: fixnum =(n<<2)|1=, nil =3=, t =7=, otherwise a pointer to the
object's 32-byte Sexp box.  The 32-byte boxes that exist only to carry a
value between functions (a materialised view of an immediate, a scratch
copy, an out-parameter slot) go away.

The heap object layout does NOT change: cons, string, vector and record
objects keep their 32-byte Sexp header box and their existing payload
layout, and containers keep storing WORDs (Doc 147).  A pointer WORD is
still the address of an object's 32-byte box; what disappears is the
box that is allocated per read or per call to carry a value.

Out of scope until eval/bytecode-20261018 merges: =wf_bytecode_*=, which
that lane rebuilds on words.  =m5_fx_*= and =nl_fx_*= belong to the
eval-s2s3 lane; edits there are coordinated first.

* Census

=nelisp-standalone--box-census-record= runs for every unit built by
=nelisp-standalone--cached-unit= (and the driver), on the unit source after
all source patches and before the inliner, when =NELISP_BOX_CENSUS= names a
file.  It counts call heads per unit: =(alloc-bytes 32 8)=, the =*_ptr=
materialisers (=nl_cons_car_ptr=, =nl_cons_cdr_ptr=, =record-slot-ref-ptr=,
=vector-ref-ptr=, =nl_vector_slot_ptr=, =nl_record_slot_ptr=), every
=*_clone_into=, =wf_copy32=, =nl_root_reserve=, and the two ABI shims
=nl_val_store_word= (box -> word) and =nl_sci_store_imm= (word -> box),
which are remaining debt.  Counting before the inliner is deliberate: an
inlined helper body would otherwise be counted once per call site, and the
inliner only runs on a cache miss.  =tools/ai/box-census.py= summarises the
file per idiom and per unit family.

* Rooting rule

Facts, read from the source at e0ab2ae3a:

1. Nothing moves in production.  =268435608= (compaction) is written 0 at
   boot (Doc 152 §11.21).  =nl_gc_collect= compacts only when that flag is
   1 *and* the conservative scan pinned nothing.  The mid-form collector
   (=nl_gc_midform_collect= -> =nl_gc_collect_from_recorded_roots 0=), the
   parked collector used under live workers, and the explicit
   =garbage-collect= builtin are always mark+sweep.  So =nl_gc_compact=
   cannot run mid-form, and a pointer WORD's value stays valid for the
   object's lifetime.
2. The conservative scan pins.  =nl_gc_conserv_maybe= walks the main
   thread's native stack from the current =rsp= to the driver-entry top
   (=268436456=), resolves each word to its owning block, marks it 4
   (pinned) and scans that block's payload as opaque words, transitively.
   A pinned block is never freed by the sweep and blocks compaction.
3. The scan is on in every production mode: the driver writes =268436464 = 1=
   at boot.  Only the debug primitive op 28 turns it off (op 29 back on);
   that configuration is for proving whether a precise root arm is
   load-bearing, and it is where =m5_fx_run='s float local was lost.
4. Worker threads (Doc 199) have no native-stack scan.  Their roots are the
   recorded EvalCtx and the private reserve at =env+4096=
   (=nl_gc_mark_thread_roots=).  A collection runs only with every worker
   parked at a safepoint.
5. Root-stack slots reserved inside a binder overwrote a parallel =let='s
   pending values, which sit just above the root-stack top while it binds
   them one by one.

Rule:

- R1 (main thread).  A pointer WORD held in a native local or argument
  stays alive and valid across an allocating call or safepoint: the scan
  pins its block and nothing moves.  No root slot is needed for it.
- R2 (worker-reachable code).  A WORD that must survive a safepoint in code
  a Doc 199 worker can run must also be reachable from a precise root: the
  worker's private reserve (=nl_root_reserve=) or a rooted container.
  Converting a box to a WORD never weakens this: a fresh transport box in a
  native local was itself unrooted, and the WORD references the same
  object the box did.  A box that WAS in a root slot keeps a root slot.
- R3.  Never reserve root-stack slots inside a binder or anywhere a caller
  may hold pending values above the root-stack top (fact 5).  Reserve in
  the caller before binding starts, or keep the WORD where R1 covers it.
- R4.  A WORD read from a container is the container's own child pointer:
  it cannot be clobbered by a later lookup the way a shared scratch view
  can.  An argument that is still a scratch view (from unconverted code)
  must be converted to a WORD at the call boundary, before any lookup.
- R5.  If compaction is ever re-enabled, R1 still holds for the main
  thread because any conservative pin vetoes compaction; R2 code would need
  forwarding, which is why the parked collector never compacts.

* Coexistence ABI

- A converted function takes WORDs and returns the value WORD.  0 is never
  a valid WORD (a fixnum is odd, nil is 3, t is 7, a box pointer is
  non-null), so 0 means failure with the signal stashed (the existing
  =268435472= pending-signal stash), matching the =*_ptr= accessors' 0
  for a wrong-type container.
- Unconverted callers reach a converted callee through =nl_val_store_word=
  (32-byte slot -> WORD); a converted caller reaches an unconverted callee
  through =nl_val_load= / =nl_sci_store_imm= (WORD -> view).  Both shims
  are census debt and must reach 0 per family.
- Setters (=nl_record_set_slot=, =nl_vector_set_slot=,
  =nl_consbox_set_car/cdr=, =nelisp_cons_construct=) already accept a WORD
  for the value: they go through =nl_val_clone_into=, which stores an
  immediate WORD as it is.  A =*_ptr= read whose only consumer is a setter
  converts by passing the raw WORD.
- Families convert one at a time, cons accessors and their immediate
  callers first.  Each family's gate is its census row at 0 plus every
  behavioural gate in the ledger.

* Mechanical rewrite (short note; full section after the conversion)

=tools/ai/box-rewrite.py= reads the unit-source dump (NELISP_BOX_DUMP), runs
two call-graph fixpoints (convertible out-parameters; parameters that
already accept a WORD) and classifies each transport site as mechanical,
shim-only or manual.  Apply mode edits the SOURCE files with token-level
edits (head symbol swaps, dropped offset arguments), never a build-time
transform, so the census measures the source people read.  The manual
queue (=queue= mode, committed as tools/ai/box-manual-queue.json) lists
sites needing judgment: R2/R3 (root-stack reservations), R4 (a non-local
box passed into a convertible out position), worker-only code, raw memory
access, and unknown uses.  wf_bytecode_* and m5_fx_*/nl_fx_* are excluded.

* Builtin word ABI (eval/abi-20261018)

** Contract

- A converted builtin or producer =F_w= takes WORD / view arguments and
  returns the result WORD.  0 means "failed, signal stashed" (THROW flag
  @268435472, TAG @268435480, VAL @268435512, as every rc=1 path already
  does).  2 means "not handled" and is used only by =nl_apply_special_w=
  (the special-form dispatcher's old rc 2).  Neither 0 nor 2 is a WORD: a
  fixnum is odd, nil 3, t 7, a box pointer is >= 4096 and 8-aligned.
- Arity is kept even: a function that loses its OUT parameter takes a
  trailing =_pad= instead (callers pass 0).
- The returned WORD may be the object's own box (a cons cell's car is
  returned as the child box, not a copy).  A caller must never write into
  a WORD it received; it stores it through a setter or =nl_abi_word_to_rc=.

** Coexistence (one function at a time)

- Every converted =F= keeps its old name and (rc, OUT) ABI as a one-line
  adapter: =(defun F (.. out) (nl_abi_word_to_rc (F_w .. 0) out))=.
  =nl_abi_word_to_rc= stores an immediate with =nl_sci_store_imm= and a
  pointer WORD with a 32-byte copy (what the old =wf_copy32= arms did),
  returns 1 for 0.
- The reverse adapter =nl_abi_rc_to_word rc out= turns an unconverted rc
  form that wrote a private fresh box into a WORD: the box itself is the
  value (=nl_val_store_word=), so there is no extra copy.
- Dispatch tables: an arm is either legacy =(MATCH . RC-FORM)= (writes the
  free variable =out=) or word =(MATCH :word . WORD-FORM)=.
  =nelisp-standalone--applyfn-build-dispatch= with WORD-ABI wraps legacy
  arms as =(let ((out (alloc-bytes 32 8))) (nl_abi_rc_to_word RC-FORM out))=
  (=nelisp-standalone--applyfn-word-arm=); without WORD-ABI (other
  dispatch users) it wraps word arms as =(nl_abi_word_to_rc FORM out)=.
  =nelisp-standalone--guard-fixed-arities= keeps the marker and answers 0
  on an arity error.
- Generated dispatchers: =nelisp_apply_function_w (func args env _pad)=
  holds the dispatch; =nelisp_apply_function (func args env out)= is the
  adapter.  While an arm is still legacy it costs one private 32-byte box
  per call inside the WORD dispatcher (the callers' OUT box did the same
  job before); converting the arm removes it.

** The three blockers from the dry run

1. Callers branching on the status (191 sites).  They keep calling the old
   name through its adapter until converted.  Converting one is a local
   rewrite: =(if (= (F a out) 0) OK ERR)= becomes
   =(let ((w (F_w a 0))) (if (/= w 0) OK' ERR))= with OUT's uses in OK
   rewritten to W (tag tests, setters, cons walks as in the mechanical
   pass; =wf_copy32 dst out= becomes =(nl_abi_word_to_rc w dst)=).
2. Table-dispatched builtins (90 bf_* with no direct caller).  They are
   reached only through the dispatch table: convert the arm to =:word=
   and add =bf_X_w=; =bf_X= stays as the adapter for any remaining direct
   or table user (the reader table overrides some baked arms, e.g. car /
   cdr / eq -> bf_car / bf_cdr / bf_eq).
3. Names referenced from the compiler and tools (78).  The old names keep
   their ABI forever (adapters), so the AOT compiler's helper calls by
   string (=nl_record_set_slot=, =nl_vector_set_slot=, ...), the
   native inventory, tests and tools are untouched.  New code calls the
   =_w= names; an adapter is deleted only when no reference remains
   (grep over lisp/ scripts/ src/ test/ tools/).

** Bytecode interpreter (wf_bytecode_*, owned by eval/bytecode-20261018)

Its builtin path is =wf_bytecode_call_gateway=,
=wf_bytecode_call_interpreted_gateway=, =wf_bytecode_call_named_value=,
=wf_bytecode_nth=, =wf_bytecode_try_jit_frame= and
=wf_bytecode_unwind_cleanup= -> =nl_apply_function= (combiner, rc + OUT)
-> =nl_apply_builtin= -> =nelisp_apply_function= (now the adapter), plus
=wf_bytecode_unwind_cleanup= -> =nelisp_eval_call=.  Nothing there has to
change: the adapters keep the ABI.  To drop the per-call box store, that
lane switches those six call sites to =nl_apply_function_w= /
=nelisp_eval_call_w= once they exist and stores the WORD into its VM slot.

** Playbook landed

Dispatchers (=nelisp_apply_function_w= + adapter, builder support), arms
eq / null / not / car / cdr / cons in the shared table, and =bf_car_w=,
=bf_cdr_w=, =bf_eq_w= (reader table) with adapters.

** Failure, "not handled", and the integration passes

- =nl_abi_fail RC _pad= is the one way to answer "failed": RC is the value
  of the call that stashed the signal and is ignored; it returns 0.  When
  the THROW flag (268435472) is clear it first stashes
  =(error "nelisp: word ABI failure without a stashed signal")=, so a bare
  0 can never surface later as a garbage error.  Write
  =(nl_abi_fail (bf_wrong_type_listp a) 0)=, never =(seq ... 0)=.
- 2 ("not handled") is produced only by =nl_apply_special_w=.
  =nl_abi_word_to_rc= hands 2 through as rc 2, so the =nl_apply_special=
  adapter keeps its contract.  Every other consumer of =nl_apply_special_w=
  tests =(= w 2)= before using W; no other =_w= function may return 2.
- =F_w= keeps F's parameter list with the OUT parameter renamed to a
  =_pad= at the same position (callers pass 0).  The integration tools
  rely on this.
- =python3 tools/ai/box-apply.py flip-arms= (run once after the group
  merges) rewrites each literal arm =((MATCH) . (F .. out ..))= whose =F_w=
  exists into =((MATCH) :word . (F_w .. 0 ..))=.  Its only edits are the
  =:word= marker, the callee name and the one =out= argument (OUT is not
  bound in the word dispatcher).  Arms whose form is not a single such call
  (111 at 85cc06423, listed in tools/ai/abi-partition.json as
  =hand_arms_G4=) are converted by hand, by G4 only.
- =python3 tools/ai/box-apply.py repoint DUMP= rewrites status-testing
  call sites: a caller local O bound to =(alloc-bytes 32 8)=,
  =(= (F .. O ..) 0)= -> =(/= (setq O (F_w .. 0 ..)) 0)= (and =/== -> ===),
  O's init -> 0, O's writers and word-safe uses rewritten as in the
  mechanical pass.  Sites that do not fit stay on the adapter and are
  reported with the reason (=--json OUT=).
- =python3 tools/ai/abi-partition.py check GROUP DUMP [--arms|--defuns]=
  is the per-group gate; tools/ai/abi-progress.org runs it per stage.
