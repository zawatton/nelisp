** The round-5 audit-harness semicolon incident (and its guard)

Both of round 5's first two attempts (=round5.log=, =round5.log.prev=,
=audit-r5-attempt1-saved.log=) died in the *bootstrap* phase with
=invalid-read-syntax= on the entire flattened per-form-progress helper, and

=scripts/real-init-audit.sh= flattens into one line with =printf '%s '= for
the line-oriented bootstrap REPL -- the shell comment directly above that
block already said not to do this.  Flattened, the first =;;= commented out

** The GC root-coverage fix (landed, nelisp =d145e3c02=)

=nl_gc_conserv_word='s conservative stack scan treated an in-arena word as a
possible root only when the slot it pointed at carried a Sexp tag below 14.
Doc 200 (v1.1.0) added tag 14 (=UnibyteStr=) and tag 15 (=UnibyteMutStr=) and
taught the marker about both, but left this bound at 13 -- so a native-stack
word pointing at a slot holding a unibyte string was never pinned as a root,
the sweep freed the block under it, the free-list link overwrote the tag
byte, and the next clone of that block read stale bytes as a vector box
pointer and faulted in =nelisp_nlvector_clone=.  Named from five identical
core dumps (rejected stack word = a 40-byte block, tag 14/15, mark 0); the
fault rate rose from ~1/8 to 5/6 boots once the lib's loader started turning
every source file into a unibyte string (=2d6fa6be=), which is what made it
reproducible enough to isolate.  Fix (=d145e3c02=, nelisp repo): raise the
plausible-tag bound from =< 14= to =< 16=, the current Sexp tag universe; the
marker already handles both tags, so this only lets the scan retain more,
introducing no new dereference shape.

This is a *different* GC defect from the item below (T45); do not conflate
them.

** Key discovery: the audit is now time- and memory-bound, not error-bound
- The real-init replay runs inside ONE top-level form, and the standalone
  allocator serves blocks larger than 472 bytes by exact fit only (no
  coalescing, compaction off by policy).  Each package load strands the
  memory it freed; round 2 hit =bin/nemacs='s 8 GiB address-space cap
  (=NEMACS_NELISP_MEMORY=) and exited 88 -- that is =nl_os_alloc_fail=, not
  OOM and not a GC failure (the mid-form collector fires; live bytes stay
  flat).  The split-on-reuse fix removes a constant, not the slope; bounding
  it needs free-block coalescing, which in turn needs the root-coverage work
  Doc 152 §11.18-20 records (a coalescing prototype reshaped the heap
  correctly and then aliased a stale reference on the first package load).
- Every cold =require= of a =src/= file was paying a ~3 min *failed* AOT
  compile before falling back to source (the =random= defect above).  With
  that fixed the compile succeeds, but the loader still does not keep the
  artifact (open item, codex/artifact-cache-populate); until it does, a full
  replay is ~3-4 h per 200 forms.
- =round 3= shows the residual error surface is small: the two =nelix= rows
  are the user's environment (=nelix.el= is not on =load-path= under GNU
  either), the exec-path-from-shell row is fixed upstream, and the undo-tree
  limits row is fixed.  The evil rows (form 206+) are not yet reached.

* 1. Purpose

The self-hosted NeLisp standalone interpreter (binary =b1k21-v48=, md5
=3def003a=) runs the user's real Emacs =init.el= (~930 forms:
evil / treemacs / org / ddskk / doom-dracula / flycheck / transient /
centaur-tabs). The startup audit already completes at *4/4*
(=loaded=1 / startup-hooks-run=1 / error=nil / doom-dracula theme
reflected=), but the clean run (=/tmp/err-c9=, 2026-07-19) still emits
*238 caught errors*.

The completion criterion for "Emacs replacement complete" is:

: caught-error 0  +  ddskk really loads  +  4/4

with the hard constraint that every remaining error be driven to zero by
implementing the *missing core function / feature in real Elisp* — no-op
stubs and error-swallowing are forbidden.

This document catalogs, from the current audit, *which core capabilities
are actually missing* and lays out the implementation order. The guiding
finding: the long tail is *not* "package incompleteness" — it is a small
number of *core substrate defects* whose downstream blast radius is large.
Fix the core, and most of the tail collapses.

* 3. Root-cause analysis

** 3.1 [DOMINANT] EIEIO class system collapse — one core defect, ~60–70 errors

*** Symptom
=error: ("Given parent class %S is not a class" X)= for X in
=eieio-default-superclass= (repeated), =treemacs-scope=,
=emacsql-connection=, =emacsql--sqlite-base=, =plz-media-type= (+ its
subclasses), =plz-event-source=, and the entire =transient-*= class
family (=transient-suffix=, =transient-group=, =transient-argument=,
=transient-option=, =transient-object=, =transient-infix=,
=transient-child=, =transient-variable=, =transient-information=).
Plus the downstream =void-function transient-suffix= (17), and other
=void-function= constructors whose =defclass= never completed.

*** Confirmed root cause (static, decisive)
The *chronologically first* eieio error in =err-c9= is line 36:

: error: ("setf: unsupported place" eieio--class-parents)

*before* the first "Given parent class" at line 37. The causal chain:

1. =eieio.el:685= runs =(defclass eieio-default-superclass nil ... :abstract t)=
   → =eieio-defclass-internal= (=eieio-core.el:278=).
2. =eieio-defclass-internal= performs =(setf (eieio--class-parents newc) ...)=
   (and siblings: =eieio--class-slots=, =eieio--class-initarg-tuples=,
   =eieio--class-class-slots=, =eieio--class-children=; and the inherited
   =cl--class-parents=).
3. =eieio--class-parents= is a =cl-defstruct= slot accessor that has *no
   setf-setter registered*, so =setf= raises "unsupported place".
4. The root-class construction aborts → =eieio-default-superclass= is never
   registered as a valid =cl--class= (=(setq eieio-default-superclass
   (cl--find-class 'eieio-default-superclass))= at =eieio.el:690= yields a
   non-class).
5. Every later =(defclass foo () ...)= defaults its parent to
   =eieio-default-superclass=, calls =(cl--find-class 'eieio-default-superclass)=,
   finds it is not =eieio--class-p= → "Given parent class ... is not a class".

*** Why the accessor has no setter — the exact core defect
The *active* =cl-defstruct= is the *prelude* version
(=vendor/nelisp/lisp/nelisp-cl-macros.el:472=), baked into the standalone
binary. (The correct =src/emacs-cl-macros.el= version, which handles setf, is
=fboundp=-gated and therefore *skipped* — the recurring "prelude macro beats
the correct src version" meta-pattern.)

The prelude =setf= is record-aware and *does* have a struct-accessor
resolution path: at =nelisp-cl-macros.el:1174= it looks the accessor up in the
alist =nelisp-cl-macros--accessor-info= (accessor → slot index) and expands
=(setf (ACC REC) V)= into =(nelisp--record-set REC IDX V)=. The record
mutator =nelisp--record-set= exists (baked). So the setf machinery is fine.

*The defect is that the prelude =cl-defstruct='s main accessor-generation
loop does NOT populate =nelisp-cl-macros--accessor-info=.* At
=nelisp-cl-macros.el:638–644= it emits, for each slot in
=slot-names = (append parent-slot-names own-slot-names)=:

: (defun ACC (rec) (nelisp--record-ref rec I))

positionally indexed =I=, but never pushes =(ACC . I)= onto
=nelisp-cl-macros--accessor-info=. (A *separate*, older helper at lines
443–451 does register accessor-info, but the main =cl-defstruct= body does
not use it.) Consequently *every* struct accessor generated by the active
=cl-defstruct= — including all =eieio--class-*= and the bootstrap-defined
=cl--class-*= accessors — is invisible to =setf=, and any
=(setf (ACC rec) v)= falls through to the "unsupported place" error.

eieio is the first casualty because =eieio-defclass-internal= is the earliest
code path that mutates a struct slot via =setf=. This is a *generic* struct
defect that also hurts =ctbl:= and any other =cl-defstruct='d package type.

The bootstrap =cl--class= stand-in (=nemacs-bootstrap.repl:1021=,
slots =name docstring parents slots index-table=) is likewise defined by this
setter-less path, so =cl--class-parents= (used at =eieio-core.el:220=) is also
unregistered.

*** Slot-index inventory (record positions, 0-based; accessor index ==
=nelisp--record-ref= index, so no type-tag offset adjustment is needed —
accessor and setter use the same I)

=eieio--class= = =(:include cl--class)= + own slots:

| index | slot                       | accessor                              |
|-------+----------------------------+---------------------------------------|
|     0 | name (cl--class)           | eieio--class-name / cl--class-name    |
|     1 | docstring (cl--class)      | eieio--class-docstring                |
|     2 | parents (cl--class)        | eieio--class-parents / cl--class-parents |
|     3 | slots (cl--class)          | eieio--class-slots                    |
|     4 | index-table (cl--class)    | eieio--class-index-table              |
|     5 | children                   | eieio--class-children                 |
|     6 | initarg-tuples             | eieio--class-initarg-tuples           |
|     7 | class-slots                | eieio--class-class-slots              |
|     8 | class-allocation-values    | eieio--class-class-allocation-values  |
|     9 | default-object-cache       | eieio--class-default-object-cache     |
|    10 | options                    | eieio--class-options                  |

All 11 =eieio--class-*= setf sites in =eieio-core.el= (lines 220, 307–310,
316, 341, 347, 461, 476, 488, 493, 508, 521, 649) target this set.

*** Fix (core)
Ship =src/emacs-parity-eieio.el=, loaded *first* in the
=nemacs-next-session.el= dolist (before any package =require='s eieio at
runtime), that:

1. *Unconditionally* installs the setf-integrating =cl-defstruct= (the
   =emacs-cl-macros.el= generator, with =cl-struct-setter= registration and
   =:include= support) as the active =cl-defstruct=, overriding the prelude —
   the established unconditional-override pattern (cf. =emacs-parity-clloop.el=,
   =emacs-parity-clmacros.el=). This makes the *runtime* =eieio--class= /
   =eieio--slot= defstructs register setters.
2. Re-registers =cl-struct-setter= for the *bootstrap-defined* =cl--class=
   accessors (=cl--class-parents= etc., indices 0–4 accounting for the
   record type-tag offset), since those were already expanded by the
   setter-less prelude before any shim can load.

*** Verification (binary; machine-solo)
- =(setf (eieio--class-parents (eieio--class-make 'x)) '(a))= succeeds.
- =(eieio--class-p (cl--find-class 'eieio-default-superclass))= ⇒ =t= after a
  bare =(require 'eieio)=.
- Full audit: the ~60–70 "Given parent class" + =void-function transient-suffix=
  (17) family goes to 0; 4/4 maintained.

CAUTION: host =macroexpand= verification is necessary but *not sufficient*
(macros2 lesson). Confirm on the actual binary's source-eval path.

** 3.2 gv / setf residual places (core, small)
After the eieio fix, the remaining =setf: unsupported place= data are:
=cl-getf= (2), =if= (1), =eieio--class-parents= (already covered),
=eieio--class-parents=. These are generic =gv= places the prelude setf does
not expand:
- =(setf (cl-getf PLIST KEY) V)= — needs the =cl-getf= gv-expander
  (=plist-put= based).
- =(setf (if C A B) V)= — needs the =if= gv-expander (setf into whichever
  branch place is selected).

Fix: extend the disk-shim =setf=/=gv= layer with these two expanders (real
semantics, per =gv.el=). Not =cl-simple-setter= candidates — they are
compound places.
