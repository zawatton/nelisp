#+TITLE: GNU parity instruction budget
#+STATUS: draft

* Decision

Reduce the number of runtime boundaries crossed by ordinary Lisp operations.
The first experiment should lower a real package-load loop and a hot FX
body to word-native code, then measure the whole init. Use that experiment
to decide how much of the value, frame and symbol-cell migration must land
before expanding native coverage.

The accepted m35 baseline is 21.2 s, four replay errors and 119 passing
par rows. The preceding Fable review estimates about 20 s of m35 Lisp
execution versus 0.9 s on GNU, with about 137–160 billion versus 10 billion
user-space instructions. These are historical, workload-level estimates.
The m29 capture counted 160.83 billion Ir for the full NeLisp command and
59.80 billion for the GNU command, of which 49.60 billion were in one GNU
regexp matcher. The m33 Callgrind replay counted 139.23 billion Ir.
GNU's 6.5 s historical full replay includes a large regexp and filesystem
component. Track parity for the matched Lisp workload alongside the
end-to-end startup result.

* Measurement

The probes use the m35 executable and restored =m35.dump= on
=lane/op-budget= at =202e5889bb0f3517f75538b580656e4a31bc4dec=.
GNU 31.1 runs under =-Q --batch= with native JIT and subr trampoline
generation disabled. Dumped or precompiled GNU library functions retain
their installed implementation. Both runtimes consume the same lexical
=.el= source and, in the compiled column, the exact same GNU-produced
=.elc=. Compilation runs before profiling. The source column on m35
includes its normal FX policy. The closure, byte-code and Subr targets
are checked by callable type. Each run checks fixed expected values or registration effects. Fresh
definitions, hooks and maps are checked at three sites. The repeated
value rows check their final value. Both engines use
=gc-cons-threshold= of 100,000,000. A fresh process and a private
temporary home back each point, pinned to one of CPUs 11–14, with an
8 GiB virtual-memory limit, a timeout and closed stdin.

Top-level rows use one syntactic operation per form. Value-producing
rows store to an observable global so that the byte compiler must keep
the work. Each declaration, hook and keymap row uses its own name or
fixture. The keymap and Custom-group fixtures have identical size at all
trip counts. The two after-load rows reset =after-load-alist= to an empty
list on each iteration to hold lookup and duplicate-check work constant.
The deferred path verifies registration and invokes the last callback
via =provide= with =load-file-name= nil. The loaded path includes callback
execution and registration. The require hit uses a feature just provided
by setup and skips file I/O.

For a fair package-source comparison, each source workload starts with
a comment containing the token =require=. m35's existing dependency
heuristic selects the incremental reader and evaluator at every count.
The comment has no Lisp semantics. Under the default hybrid routing,
=defun= spans 22,559 bytes at 512 forms and 39,455 bytes at 896 forms.
Crossing the 32 KiB threshold changes the path, so a single slope across
that boundary would mix the costs of two implementations.

Callgrind counts user-space guest instructions. Kernel work, wall time

* Paths and structural costs

** Common path

The package-source reader probe is visible once per form through
=bf_read_all_from_string_native_w__af0= → =bf_read_one_external_utf8_p=.
The latter costs 7.68k Ir self in the load control, before token dispatch,
interning or cons construction. The Lisp incremental driver does cursor,
window, rewrite and per-form =eval= work. Its own closures exercise FX
when admitted. The m35 =setq= control costs 89.8k Ir per form versus
9.69k on GNU. In that control alone, =m5_fx_run_body= takes 27.7k self,
=bf_read_one_external_utf8_p= 7.7k, =m5_fx_callout= 7.2k, and
=m5_fx_call_subr_resolved= 4.1k. The hot =car= site adds only 220 Ir
above the m35 source loop control. A file-level =car= slope of 109k
contains a much larger read and dispatch budget.

After the reader the source evaluator enters =nl_eval_inner_w= and
=nl_eval_inner_cons_w=, then either a special form or live function-cell
resolution and apply. Closure calls go through an FX record lookup and
shape validation when eligible. FX execution uses =m5_fx_run_body= and
its callout, with a resolved Subr route, a source apply fallback or the
GNU bytecode VM as required by the callee. Intermediate operations can
root tagged arguments or convert through a view/clone API. Binding and
debug state appear in =nl_root_frame=, =nl_n4_push_words= and
=nl_n4_finish_w=. Symbol access uses =nelisp_mirror_lookup_entry_owned=
and sometimes =nl_symcell_entry=. Canonical symbols can already resolve
directly to their own object. New interned names, syntax, closures and
Lisp results account for real allocation, plus temporary materialization
on mixed paths.

* Redesign options

The table models a first production rollout starting at 21.2 s. The
addressable budgets are scenario inputs, informed by m29 exclusive wall
groups and m33 call traces. Savings are the pool multiplied by the
assumed fraction removed. The projections use historical subsystem budgets. Measure each
pool on the m35 replay before accepting a forecast.

| Option | Addressable init pool | Fraction removed | Projected init | Effort | Main risk |
|--------+-----------------------+------------------+----------------+--------+-----------|
| A. Lower FX and load-loop control flow | 4.2–5.2 s | 60–80% | 17.0–18.7 s | 4–8 engineer-weeks | Analysis or code-cache cost moves onto first call |
| B. Unify managed values and frame slots | 4.3–5.8 s | 55–75% | 16.9–18.8 s | 10–18 engineer-weeks | Root visibility, object identity and image migration |
| C. Use the live symbol cell directly | 2.5–3.5 s | 50–75% | 18.6–20.0 s | 4–8 engineer-weeks | Stale aliases, advice or dynamically rebound state |

** A. Lower FX and load-loop control flow

Compile a loader loop that retains a rooted source cursor and alternates
read, macro-alias handling and evaluation one form at a time. The loader
still sees macros and local declarations installed by earlier forms.
Make the FX baseline a threaded stream with fused common operations and
a guarded slow entry. Lower admitted hot FX blocks to native code using
Doc 248's instruction encoders, register and spill machinery and
relocations. Its GNU LIMPLE frontend and GNU =.eln= ABI remain specific

* Acceptance and parity target

With the scenario pools above and a 0.5–1.0 s allowance for overlap
between the high and low scenarios, the joint first rollout projects
roughly 10.6–16.1 s, with a central scenario near 14 s. This is a
rollout checkpoint. Full Lisp parity needs roughly 93% fewer Ir from a
137 billion starting budget to reach 10 billion, and an approximately
22-fold change in measured Lisp elapsed time from the quoted 20 s to
0.9 s. Even 5% of the current Lisp time left unchanged consumes one
second. Broad lowering and cheaper value and cell paths must reach the
bulk of dynamic source, vendor bytecode and init callbacks. A useful
later target is 2–3 s overall if a 1.2 s non-Lisp remainder is confirmed
and the Lisp component reaches 0.9–1.8 s. Time the complete matched
replay before making a startup parity claim.

Capture a fresh m35 and GNU replay instruction breakdown with the same
inputs before committing the seconds budget. For each cohort, compare
per-route operation rows, replay Ir, paired native wall time, first-call
cost, fault and allocation counts, and the journal, Evil, Eat, diff-hl
and Org phases. Verify GNU source and the common =.elc= against the
fixture output. Run the 12 quick rows and all 119 accepted m35 par rows
against the pinned GNU goldens, and compare init form/skip/error counts
and material effects. Add fault-level controls for invalidation,
debugging, nonlocal exits, captured mutation and collection. Retain a
general semantic route and test it with each fast route disabled.
These are acceptance criteria for the proposed implementation.
