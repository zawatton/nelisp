#+TITLE: 246 Single-owner rule for GNU names (prelude vs emacs-lib vs vendor)
#+STATUS: ACCEPTED
#+DATE: 2026-11-25

* Problem

The same GNU name is often defined in more than one layer. Some
definitions sit in the NeLisp core (scripts/nelisp-stdlib-prelude.el,
lisp/, src/), others in the Emacs compatibility layer
(packages/emacs-lib-core/src/), and many of these are fboundp-guarded
fallbacks. A static count on 2026-11-25 found 560 names defined in both
the core and emacs-lib.

Which definition is live then depends on load order and guards. Two
cases from that period show the problem:
- The category tables mixed the prelude define-category with the
  emacs-lib standard-category-table.
- A charprop stub hid the genuine registry.

* Rule

1. *One definition per name.* GNU decides where a name lives:
   - *GNU Lisp* (lisp/**/*.el): only the verbatim vendor file defines
     it. Never reimplement it in NeLisp code.
   - *GNU C, language core*: eval.c, data.c, fns.c, alloc.c, lread.c,
     print.c, bytecode.c, floatfns.c, and the string, number and list
     parts of editfns.c. These are ported into the NeLisp core
     (prelude / lisp/).
   - *GNU C, editor substrate*: buffer.c, editfns.c (buffer parts),
     fileio.c, dired.c, keymap.c, syntax.c, search.c (buffer
     regexps), casefiddle.c, coding.c, charset.c, window.c, frame.c,
     process.c, textprop.c, minibuf.c, and similar. These are ported
     into emacs-lib.
   - *Exception.* A C facility that a core consumer needs (the reader,
     the regex engine, the printer) lives in the core, even when GNU
     keeps it in chartab.c, category.c or casetab.c. emacs-lib must
     not redefine it; it may only call it.
2. *No fallbacks.* No fboundp/boundp-guarded copy of a name owned by
   another layer. Host-Emacs fallbacks are no longer needed because
   emacs-lib is not run on host GNU Emacs, so delete them.
3. *Wrapping.* A layer that needs different behaviour uses the
   owner's hook or variable, or an advice-free extension point, and
   documents it in the owner. It does not redefine the name.
4. *Gate.* The count of names defined in more than one layer is
   reported as gate G2-dup and must only go down. A new duplicate is
   a failure.

* Measuring

The gate status script counts, at the definition level, the names
defined in both the core and emacs-lib. It also counts the GNU
vendor-file names whose live definition is not the vendor file (G2).
Both counts are expected to reach 0, except for an explicit,
justified allowlist.

** Round 5 follow-up on =message=

GNU 31.1 registers =message= as the C subr =Fmessage= in =src/editfns.c=.
It returns nil or the original empty string when clearing the echo area.
For other arguments it calls =Fformat_message= and passes the resulting
string to =message3= in =src/xdisp.c=.  That routine logs the message before
checking =inhibit-message=.  The display path writes encoded bytes and a
newline to stderr for the initial batch frame.  For an interactive
frame it updates the minibuffer's echo area and runs redisplay against
the selected frame and terminal.  These are services of the GNU C
editor, frame and terminal state.
[[https://github.com/emacs-mirror/emacs/blob/emacs-31.1/src/editfns.c][GNU editfns.c]]
[[https://github.com/emacs-mirror/emacs/blob/emacs-31.1/src/xdisp.c][GNU xdisp.c]]

The proposed NeLisp boundary is the existing standalone core entry
point in =scripts/nelisp-stdlib-prelude.el=.  Once the editor is loaded it
delegates to =emacs-special-buffers-message= for the NeLisp message log,
echo-area state and batch stderr.  Editor bridges use that entry point.
This identifies where NeLisp must supply the C primitive's behaviour
and leaves the exception for owner review.  Its output, return value
and clear and inhibit behaviour remain subject to GNU parity.

* Round 5 owner decision on =message= (2026-11-26)

The project owner approved =message= as a substrate boundary, the same class
as the other approved names: GNU 31.1 implements it as the C subr =Fmessage=
(src/editfns.c) feeding =message3= and the echo-area/redisplay machinery in
src/xdisp.c, so NeLisp supplies it from its own runtime.  The approved set is
now 17 names (the 16 above plus =message=); the 4 performance shims still have
to return to GNU after the init speed gate.
