#+TITLE: Doc 225 — Syntax lookups and the string-match entry path: GNU 31.1 parity
#+STATUS: IN PROGRESS
#+LEDGER: tools/ai/syntax-rt-progress.org

* §0 Goal

Make =char-syntax=, a syntax-class =string-match= and a plain =string-match=
as fast as GNU Emacs 31.1 in wall-clock time by reproducing GNU's
structure: syntax tables that are char-tables holding raw syntax
descriptors, a standard table populated once instead of computed per
lookup, a per-character syntax test that reads the table directly, and a
string-match entry that reads the case-canonical table once and translates
each character with one char-table read.  Speed comes from removing work
the GNU structure never does; no new native function is added (AGENTS.md,
minimal native surface).

* §2 The GNU mechanisms

- *Entry.*  syntax.h:107 =SYNTAX_ENTRY= is =CHAR_TABLE_REF= on
  =BVAR (current_buffer, syntax_table)=; syntax.h:116-135 take the class
  from the entry's car with =& 0xff=, a non-cons entry meaning
  whitespace.  syntax.c:1098-1117 =Fchar_syntax= adds only
  CHECK_CHARACTER and =syntax_code_spec[]= (syntax.c:1084).
- *Tables.*  A syntax table is a char-table of subtype =syntax-table=
  with no extra slots (syntax.c:3672).  Entries are raw descriptors
  =(CODE . MATCH)=: class in bits 0-15, flags 1234pbnc in bits 16-23
  (=Fstring_to_syntax=, syntax.c:1151).  Entries without a matching
  character or flags are shared conses (=Vsyntax_code_object=,
  syntax.c:3667-3669).  =make-syntax-table= (subr.el:6547) makes an empty
  char-table whose parent is the standard table; =copy-syntax-table=
  (syntax.c:1019) copies, clears the default and gives the copy a parent.
- *Lookup.*  chartab.c:225 =char_table_ref= reads the ASCII sub-table or
  =contents[CHARTAB_IDX]= and descends sub-char-tables, then the default,
  then the parent; lisp.h:2133-2155 inline the ASCII case.  Every
  character has an entry in the standard table: control characters are
  punctuation, letters and digits word, =0x80..MAX_CHAR= word
  (syntax.c:3678-3738), and characters.el refines Unicode.  394 runs result.
- *Regexp cache.*  search.c:199-262 =compile_pattern= walks an MRU list
  and compares pattern text, translate table, posix flag, whitespace
  regexp and, for syntax-dependent programs, the syntax table by identity
  (search.c:222).  syntax.c:1229-1262 =modify-syntax-entry= calls
  =clear_regexp_cache= (search.c:160), which drops every syntax-dependent
  entry.
- *Per-character test.*  regex-emacs.c:5175-5200 =syntaxspec= fetches the
  character and compares =SYNTAX (c)=; the syntax table is set up once per
  search (=RE_SETUP_SYNTAX_TABLE_FOR_OBJECT=, regex-emacs.c:3462).
- *Case folding.*  search.c:370-440 =string_match_1= passes
  =BVAR (current_buffer, case_canon_table)= as the translate table when
  =case-fold-search= is non-nil (search.c:405-410).  Each character is
  translated by =RE_TRANSLATE= = =char_table_translate= (character.h:592):
  one =CHAR_TABLE_REF= and a CHARACTERP test.

* §3 Port plan, in order of wall-clock payoff

** P1 Syntax tables become char-tables (ported)

=scripts/nelisp-stdlib-prelude.el= replaces the =nelisp--syntax-table=
record (an entries hash table plus a parent link) with native char-tables
of subtype =syntax-table= holding GNU raw descriptors.  The standard table
is built once from a generated copy of GNU 31.1's 394 standard-table runs
(=nelisp--unicode-syntax-entries=, produced by
=tools/nelisp-generate-unicode.el= beside the existing class ranges), with
GNU's shared code objects and its whitespace default.  =char-syntax= reads
the current buffer's table with one =aref= and maps the code through
=syntax_code_spec=.  =string-to-syntax=, =syntax-class-to-char=,
=syntax-table-p=, =matching-paren=, =syntax-after=, =syntax-class=,
=with-syntax-table= and =copy-syntax-table= follow GNU (C functions as
Lisp, subr.el functions verbatim).  =modify-syntax-entry= stores
=string-to-syntax='s result, so flags live in the descriptor and the side
flag store goes away.  The scanner helpers (=nelisp--syntax-lookup=,
=nelisp--syntax-flags=) become one =aref= on the same entry.

Adapted: GNU's per-buffer =syntax_table= slot stays the existing
buffer-to-table map, because the =nelisp-buffer= struct has no slot for it
and buffer state belongs to the buffer-native lane.  The ambient default
for a buffer without =set-syntax-table= stays the Emacs Lisp table (Doc
204 P3); GNU's comes from the major mode, which the bare runtime does not
have.  The fixture pins GNU under explicit tables.

Adapted: the native char-table kernel stores sorted run-length intervals
and finds one by binary search (=lisp/nelisp-cc-evalport-nonenv-char-table.el=),
not GNU's sub-char-tables.  A read from the interpreter costs 1.35-1.39 us
in total, mostly the call itself.  Porting the layout changes the GC's
char-table marking (=nl_gc_mark_char_table_slots=), which the gc-port lane
owns, so it is left as is.

The foundation adapter (=packages/nelisp-emacs-foundation/src/emacs-char-table.el=)
replaces the public char-table function cells and =nelisp--syntax-lookup=
when it loads.  Like casetab (c592d7b31), the syntax code keeps the
original native primitives and dispatches on them, and the adapter's
syntax hooks accept native tables.

** P2 Per-character syntax test (ported)

=lisp/nelisp-stdlib-regexp.el= reads the current syntax table once per
match and tests each character with =(aref table c)= and the entry's car,
as regex-emacs.c:5195 does, instead of calling =char-syntax= (which
re-fetches the table and re-checks its argument).  The bootstrap record
reader =nlre--bootstrap-syntax-class= and its ASCII string go away.

** P3 string-match entry and case folding (ported)

The entry reads the current case-canonical table once per call, through
the native extra-slot read, as =string_match_1= reads the buffer slot.
Each character is translated as =char_table_translate= does: one =aref= on
a native char-table and a character test.  Only a non-native table (the
foundation adapter's) takes the old dispatch.

** Not ported

- GNU's compiled regexp program and =re_match_2_internal= (regex-emacs.c):
  the AST matcher and its plans stay.  Porting the engine is larger than
  this lane's entry-path scope.
- GNU's sub-char-table layout: see P1.

* §4 What remains, and which layer blocks it

GNU's own costs, measured with the checker's harness (call minus a
same-shape trivial subr call, median of five in-process samples): about
0 us for =char-syntax= (within ±0.02 us of =(characterp 97)=), 0.14 us for
=(string-match "alpha" "alpha")= and 0.20 us for =(string-match "\\sw+"
"alpha")=.

In the base runtime one interpreted call of a one-argument =defun= costs
1.0-3.5 us, a call of a GNU byte-compiled function in the standalone VM
2.9 us, and a trivial subr call about 0.8 us.  A small function measured
4.0 us interpreted and 11.3 us as VM byte-code (the same function
byte-compiled by GNU 31.1 and installed with =make-byte-code=).  After P1-P3 =char-syntax= is still a
Lisp function (AGENTS.md forbids a native for speed), so its own cost is
at least one interpreted call plus its forms.  Reaching GNU's own cost
needs Lisp compiled to native code (the codegen lane) and a cheaper call
path (the callpath lane).  The S1.2 and S1.3 results record the measured
own costs against GNU's.
