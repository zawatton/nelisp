* Why this document exists

After Doc 242 a bare start of build33 takes 14.7 M Ir and about 7.1 ms.
=--version=, which exits before cold-load, already takes 7.2 M Ir (4.3 M of
it in ld.so for 19 shared libraries) and 2.6 ms.  The user chose to attack
the other 7.5 M Ir (cold-load, reinit and evaluation) first; lazy dynamic
linking is out of scope.

- The environment alone costs 2.49 M Ir, about 44 k Ir per variable.  It is
  spent inside the =<cold-boot>= reinit source
  (=nelisp-standalone--cold-boot-reinit-source=): rebuilding
  =process-environment= from =nelisp--environment= and
  =emacs-os-detect-and-set-dirs!=, run as m5 code.
- Identity (address-keyed) hash tables carry the process epoch (word at
  268436376) and their own payload address in meta slots 6 and 7.  After a
  cold load the epoch differs, so each table is reindexed on first use
  (=nl_ht_reindex=, 0.89 M Ir self).  On the v5 fast path no object moves.
- Wall time is mostly kernel time; huge-page faults cost about 0.8 ms and
  disabling THP makes the start slower, so THP stays.

* Design

** D1 Environment reinit (S1)

Find which part of the reinit is per-variable expensive (the
=process-environment= rebuild, =getenv=, or the directory detection) and
make it linear and cheap: for example build =process-environment= with
direct string construction in the runtime instead of an m5 =mapcar= +
=concat= per cell, and avoid repeated linear =getenv= scans.  Results must
match build33 exactly under the MIN, SYN and ALT environments of the ledger.

** D2 Keep identity tables valid on the fast path (S2)

When the v5 image is mapped at its recorded base with no relocation,
addresses equal the dumping process's, so identity hashes stay valid.  Carry
the dumped epoch over (or mark restored tables as current) on the fast path
only; the relocation fallback keeps the lazy reindex.  The epoch's other
users (anything that bumps it, such as a moving collection) must be checked
before the change.

* Out of scope

- Dynamic-linking cost (ld.so, 19 libraries).
- Windows and macOS, which keep the v4 image.
